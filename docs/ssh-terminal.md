# SSH Terminal

SSH Terminal opens an interactive shell on a host saved on this iPhone or iPad. It does not run through the Oppi server and does not change Pi session ownership.

## Set up a host

1. Open **Settings → SSH Hosts**, or **Terminal** below **MCP Servers** in the workspace sidebar. Both open the host list. Opening the list does not dial and does not read the Keychain, so it does not ask for Face ID.
2. Tap **Add**. Enter a host, port (default 22), and username. The host has no default. Enable Remote Login or `sshd` on that host. **Edit** opens the same form for a saved host.
3. Choose **Password** or **This Device’s Key**.
   - **Password:** enter the password at connect. **Save Password** is optional.
   - **This Device’s Key:** copy the public key and add it as one line to `~/.ssh/authorized_keys` on the host. Oppi does not install it for you.
4. Tap **Connect**. Compare the displayed host-key fingerprint with the host’s fingerprint through an independent, trusted channel. Trust it only after they match. Oppi sends no credentials before host-key validation succeeds. You can also tap **Save Host** and connect later from the list.

For example, on a Mac with an Ed25519 host key:

```sh
ssh-keygen -lf /etc/ssh/ssh_host_ed25519_key.pub
```

**Terminal** sits directly below **MCP Servers** in the workspace sidebar, whether or not a host is saved. With none saved, the list leads with **Add Host**. Tap a row to connect and open the shell. The password sheet and host-key prompt appear on the list or the form, whichever you tapped Connect from. A row shows `user@host`, the port when it is not 22, and the Run on Connect command, or **Login shell**. Two rows can use the same machine with different Run on Connect commands. A row also lists each folder a terminal is open in (`Connected in ~/workspace/oppi`). Swipe **Delete Host** removes that saved host and its password only. **Edit Host** in the live terminal opens the form for the connected host. **Tailscale → Check a Machine for Oppi** is a separate check.

## Open Terminal here

A workspace's **Terminal** button (top right, beside **Config**) and a chat's **Terminal** button open that folder on the saved host that serves the workspace's server:

- from a workspace: the workspace's root folder;
- from a chat: the session's own worktree folder when it runs in one, else its workspace's root folder.

Where the folder opens depends on the selected host's **Run on Connect** command. Its first word decides, by name, so `/Users/you/.local/bin/herdr` and `herdr --attach` count as Herdr:

| First word | Where the folder opens |
|---|---|
| `herdr` | Inside the Herdr session the host's own terminal already runs. |
| `tmux` | In a terminal of its own, attached to that folder's tmux session. |
| anything else, or no command | A login shell (fish, zsh, bash) in the folder. |

**Herdr.** The host's own terminal opens — the one its Run on Connect command starts — and Oppi asks Herdr, over that terminal's side channel, to show the folder. Nothing is typed into Herdr. If a Herdr workspace already has a pane in that folder, Oppi focuses it (`herdr workspace focus`); the folder counts in either spelling, so a mount reached through a symlink (`/tmp` on macOS) matches the path Herdr reports instead of opening a second workspace. A subfolder is a different place to work, so it gets one of its own. Otherwise Oppi creates a workspace in the folder with `herdr workspace create --cwd <folder> --label <name> --focus`, or, for a chat in a git worktree, opens that checkout as a worktree with `herdr worktree open --path <worktree> --label <name> --focus`. The label is the Oppi workspace, plus the worktree's name when the folder is one. Focusing moves the Herdr session's focus, so any other client attached to that session follows it too. If Herdr is not running yet, or it refuses, a notice says so, offers **Retry**, and leaves you in the Herdr terminal — start Herdr by hand there, then Retry opens the folder without reconnecting.

**tmux.** A folder gets a terminal of its own that enters the folder and then runs `tmux new -A -s <session>`, so the first time it creates the session there and afterwards attaches the same session, which survives a disconnect. It does not pass the folder to tmux: tmux reads `#{}` and `#()` as formats in its arguments and starts in the home folder when it cannot enter the one it was given, so the shell changes folder first, reports a missing folder instead of opening a session elsewhere, and the new session starts in that folder. The session is named after the workspace (and its worktree) plus a short hash of the folder, so two workspaces that share a name never attach each other's session; tmux does not allow `.` or `:` in a session name, so those become `-`, and a `#` in a name is doubled so tmux keeps it literal.

**Anything else.** A folder terminal starts your login shell in that folder and ignores the host's Run on Connect command. It is a separate terminal from the host's own, so it never types into a program that host already runs: the host list's row still opens that host's login shell or its Run on Connect command, and that terminal keeps running.

Every value that comes from the server — the folder, the workspace name, the worktree name — reaches the host as octal-escaped bytes inside one quoted command word, and the shell that runs the command rebuilds it there, so none of them is ever read as shell code: spaces, quotes, `$`, backticks, `;`, newlines, and non-ASCII all work, and no folder name can be talked into running commands. A `~` folder is expanded to the host's own home; Herdr's CLI takes a path, so Oppi reads that home over SSH and passes the absolute path. A missing folder says `oppi: /that/path: no such folder` and ends instead of opening a shell or a session somewhere else, in the plain shell and in tmux alike. A workspace with no host folder to open — a sandbox workspace, or one whose folder is relative to the server's working directory — does not offer Terminal; the button gives its place to the other actions.

Which host: Oppi matches the workspace's server host against the saved SSH hosts, ignoring case and a trailing dot, and treating a tailnet short name (`mac-studio`) and its full name (`mac-studio.tail1234.ts.net`) as the same machine. A saved host whose address is exactly the server's comes first, then one reached by that short-name match. Within either kind it takes a host whose Run on Connect command starts a multiplexer (`herdr` or `tmux`) before a host with no command, then a host running anything else, then the first saved one, so saving a machine twice — once with `herdr`, once plain — still opens the folder inside Herdr. With no match, **Add Host** opens with the server's host filled in and the username empty; saving it then continues into that folder's terminal.

A folder terminal is its own terminal, kept while it is connected like any other: leaving the workspace or chat keeps it, tapping Terminal there again returns to the same shell. Oppi keeps one terminal per saved host and folder, so the same host can have its own terminal plus one per folder. In Herdr the folder opens in the host's own terminal rather than a second one, so there is one Herdr client per host and it shows whichever folder you last asked for. Editing or deleting the host ends them, and so does the background grace.

In a chat, the top bar shows the buttons chosen in Settings → **Chat** → **Top Bar**: **Files**, **Git**, **Outline**, **Context** (the usage ring), and **Terminal**, each one on or off and in the chosen order, with **…** always last; **Customize Top Bar…** in that menu opens the same page. **Terminal** is one of the buttons you choose there, and it is offered in a chat whose workspace has a folder on the server; a button the chat cannot offer is not shown at all.

## Font and icons

The terminal uses **Settings → Text → Code Font** and **Code Text Size**, like code blocks and tool output. At 100% it is 13 pt. Changing either redraws an open terminal and resizes the remote shell to the new cell size.

Prompt icons from starship, powerlevel10k, oh-my-posh, and similar (Powerline separators, git, folder, and language icons) come from the bundled Nerd Fonts Symbols font, which works with every code font.

## Images

The terminal draws images sent with the [Kitty graphics protocol](https://sw.kovidgoyal.net/kitty/graphics-protocol/), so `kitten icat`, chafa, timg, `viu`, Yazi previews, and an agent's image output (`pi` printing a screenshot) appear in the grid instead of as escape-code garbage. A program that asks whether images are supported (`a=q`, which `kitten icat` does first) is told yes, so it sends the picture instead of falling back to text.

- Images are sent inside the escape code (the direct `t=d` medium), as RGBA, RGB, zlib-compressed, or PNG data. PNG is decoded on this device with ImageIO, and only PNG: a payload marked as PNG that does not start with the PNG signature, or that ImageIO does not read as PNG, is refused with `EINVAL: invalid data`, so JPEG, HEIC, TIFF, GIF, or other image data never reaches another decoder. The file, temporary-file, and shared-memory mediums are refused with `EINVAL: unsupported medium` and nothing is read: a host reached over SSH must never be able to make this app open a local file.
- Each screen (the main screen and the alternate screen) keeps up to 64 MB of decoded images. Past that, libghostty drops the oldest image to make room, and an image larger than the limit is rejected. This covers a handful of full-window pictures from a photo-heavy listing. A PNG is checked against that same 64 MB from its header, before ImageIO decodes a pixel, so a small PNG that merely declares a huge picture is refused instead of decoded; dimensions above 10000 pixels a side are refused too. The 64 MB bounds what is stored and what PNG decoding asks for, not what receiving an image costs. libghostty buffers up to 400 MiB of received image data and inflates up to 400 MiB more (growing the buffer by reallocation), so a host that sends a hostile image can briefly push memory use to around 1.1–1.2 GB while it arrives; PNG decoding itself is held to 64 MB. That spike may end the app on a device short of memory. This is a known limit of the bundled libghostty.
- Placements are drawn at their cell, honoring the protocol's source rectangle, cell or pixel size, aspect ratio, and z-index: a negative z draws under the text, a z below −1073741824 (half of the most negative 32-bit value) draws under the cell background too, and zero or positive draws over the text. Everything is clipped by the terminal's grid.
- One frame draws at most 256 images and 1024 placements, so a host printing thousands of tiny pictures cannot turn a single frame into thousands of draw calls. Image textures are budgeted at four thirds of a full store on each screen (about 171 MB for both), because only RGB and RGBA pictures are stored and RGB becomes RGBA on the GPU, so a screen of images that fits the store is never re-uploaded just to make room for itself.
- Images are pinned to their rows, so they scroll with the history like text and shift with the cursor row when the chat bar covers it.
- A delete (`a=d`), a retransmission of the same image id, and a full reset (RIS) all take effect: the picture is replaced or removed.
- Pixels reach the GPU once per image, and only again when that image is retransmitted. Frames that do not change an image copy no pixels, and an image that scrolls out of view and back is not copied again.

The Unicode-placeholder form of the protocol (the `U=1` virtual placement a program uses to show images through tmux) does not draw yet. libghostty reports no position for a virtual placement: its render info says the placement is not visible and the viewport, rect, and grid-size calls return no value, so an embedder has to find the `U+10EEEE` placeholder cells itself, decode the row and column from their combining diacritics and the image id from their foreground color (including the rules for omitted diacritics), and size each tile from the virtual placement. Until then those cells stay blank. Real placements are unaffected, so `kitten icat` inside tmux still shows nothing, while the same command outside tmux works.

## Run on Connect

**Run on Connect** runs one command in the terminal instead of a login shell. This is the same exec-with-TTY request as `ssh -t host 'command'` or OpenSSH `RemoteCommand` with `RequestTTY yes`. Enter `herdr` to attach your Herdr session, or `tmux new -A -s main` for tmux. The connection ends when the command exits and the status names the command; **Reconnect** runs it again. The command must be on the `PATH` that non-interactive SSH commands see. Leave it empty for a normal login shell. A [folder terminal](#open-terminal-here) reads it too: if its first word is `herdr` or `tmux`, the folder opens inside that multiplexer instead of in a plain login shell.

## Input bar, touch, and keyboard

The terminal picks its input from what the host tells it; it does not inspect the host's processes. A program that reports [OSC 7501](#program-status-osc-7501) on the root record as a coding agent gets the chat input bar. The agent ids are `pi`, `claude`, `codex`, `opencode`, `gemini`, `amp`, `aider`, `goose`, `crush`, `droid`, `cursor-agent`, `qwen`, `kimi`, `copilot`, `kilo`, and `grok`, also with a suffix such as `claude-code`. When **Run on Connect** starts `herdr`, the terminal is a Herdr client for the whole connection and gets the chat bar while Herdr's focused pane runs an agent. Anything else, such as a shell, `vim`, `tmux`, a program that does not report, a cleared root, or a report sent before the shell's latest prompt (OSC 133), gets direct terminal typing: the bar is hidden and a tap opens the keyboard with the Esc/Tab/Ctrl/arrow bar. Coding agents that do not report OSC 7501 yet (OpenCode, Copilot CLI, Gemini CLI, and others) start in direct typing; switch to the chat bar by hand. Herdr started by typing `herdr` in a login shell is not detected either. To switch by hand, use **Use Chat Bar** or **Type in Terminal** in the … menu, or the chat button on the terminal keyboard's bar; that choice wins until the detected program changes.

The chat input bar is Oppi's chat composer. Type or dictate (same dictation as chat), edit, then **Send**: Oppi pastes the text as one block (bracketed paste when the app supports it) and presses Enter. Send with an empty bar presses Enter alone. Autocorrect, capitals, and smart punctuation are off. While the bar is focused, a key strip offers the program's keys (such as Thinking and Model), then the arrows, then Esc, Tab, Ctrl-C, and Ctrl-D in one row; swipe it for the keys that do not fit. A keyboard button, pinned at its right end, switches to typing straight into the terminal with the Esc/Tab/Ctrl/arrow bar. That switch stays in direct typing. A tap with the keyboard down opens it, including when the app asked for mouse input. While that keyboard is up and the app asked for mouse input, a tap is a click at the cell and the keyboard stays up; hide it with ⌄ on the keyboard bar. That bar has two rows: Esc, Ctrl, Alt, Tab, and the arrows, then Paste and the program's keys. Swipe either row to reach keys that do not fit; both move together. The chat button and ⌄ stay pinned at the right end, stacked on a tinted dock. Otherwise a tap hides the keyboard. **Use Chat Bar** (in the … menu, or the chat button on the terminal keyboard) returns to the input bar. Starting an agent from the terminal keyboard moves typing to the input bar.

The chat bar grows over the terminal instead of shrinking it. The terminal keeps room for the bar at rest: one line, plus its row of buttons and key strip while that row shows (while the bar is focused, or while it holds an attachment). A longer draft, attachments, file pills, suggestions, and the dictation or send-failure note cover the bottom rows instead, so the remote terminal is not resized while you compose and the program does not redraw. When the bar covers the row the program's cursor is on, the terminal's picture moves up by the fewest whole rows that keep that row above the bar, and moves back when the bar shrinks; the top rows slide under the top edge meanwhile. While you read history, or while a finger is on the terminal or a flick coasts, the picture holds still; it eases into place once you are back to live. The remote terminal is resized when the keyboard comes up or goes down, on rotation, and when the chat bar appears or goes away.

### Program shortcuts

The key strip and the terminal keyboard's bar add buttons for the agent that reports itself (or the shell when none does), named by what they do. Each button sends the key that program has bound right now:

| Program | Buttons (default key) | User file read |
|---|---|---|
| Shell | History (^R), Clear (^L) | none |
| pi | Thinking (⇧Tab), Model (^L), Tools (^O); Stop when interrupt is not Esc | `${PI_CODING_AGENT_DIR:-~/.pi/agent}/keybindings.json` |
| Claude Code | Mode (⇧Tab), Model (⌥P), Transcript (^O), Todos (^T), Background (^B) | `${CLAUDE_CONFIG_DIR:-~/.claude}/keybindings.json`, contexts Global, Chat, Task |
| Codex | Transcript (^T), Effort − (⌥,), Effort + (⌥.); Stop when interrupt is not Esc | `[tui.keymap.*]` in `${CODEX_HOME:-~/.codex}/config.toml` |

The file is read once each time that program changes, through a side command on the same connection, and follows that program's rules: pi and Codex entries replace an action's keys and `[]` removes it; Claude Code entries add keys, and a default key bound to `null` or to another action stops counting. A missing or unreadable file means the defaults. For Codex only the `tui` tables leave the host, and only table headers, dotted keys, and string arrays are read (not inline tables, profiles, or project `.codex/config.toml`). The variables are those of a non-interactive SSH command, which may differ from the agent's own environment. Actions bound to Esc, ^C, Tab, ↑ or ↓ are not repeated, `super`/`cmd` keys are left out, and Claude Code chords are sent as one write. Other agents get the fixed keys only. Under Herdr, the buttons follow the agent in the focused pane.

Photos and files from **+** or a pasted image are saved on the host before Send, in an owner-only `oppi-ssh-<your uid>` folder under `$TMPDIR` (or under `/tmp` when the host sets no `$TMPDIR`), over the same SSH connection. The name is yours alone, so another user on a shared `/tmp` cannot create or own it first. The save is refused, with its reason shown in place of the path, when that folder is a symlink, is not a directory, or belongs to another user, and the folder is always made owner-only (700). The prompt then lists each file's path on its own line, so the agent can read it. Each file is limited to 32 MB.

A password prompt on screen turns on the keyboard's secure entry, and the bar shows **Secure Input** with a lock. Third-party keyboards, dictation, and keyboard learning then do not see what is typed. Oppi recognizes a prompt from the cursor's own line on the live screen, so it works for `sudo`, `su`, `ssh`, and `ssh-agent` in a normal shell and inside a Herdr pane, and typing `echo Password:` at a shell prompt does not turn it on. It stays on while the secret is typed, including the `*` a prompt echoes after each key, and ends when the cursor leaves that line. Reading local history does not end it. If the chat bar is the input at that moment, typing moves to the terminal until the prompt ends, then back; switching by hand meanwhile wins, and hiding the keyboard during the prompt brings the bar back at the end without reopening the keyboard. A single half-drawn frame does not end it: two frames have to agree before secure entry and the input bar change back. A password is never typed into the chat bar's draft.

- In direct typing, holding ⌫ repeats, on the on-screen keyboard and on a hardware keyboard. After about a second of holding, each repeat deletes a word (Ctrl-W, in the app's keyboard protocol) instead of a character, as in iOS text fields; letting go starts over with characters. Words are deleted only on the normal screen (shells and agent prompts such as pi or Claude Code). A full-screen app on the alternate screen (vim, nano, less, Emacs) keeps getting ⌫, since it may bind Ctrl-W to something else.
- Touch and hold the space bar, then slide, to move the cursor: one ← or → per character cell of travel and one ↑ or ↓ per row, sent once per frame in the app's cursor-key mode. In a shell, ↑ and ↓ walk the command history. The trackpad moves nothing while a keyboard such as Japanese is composing.
- Keys and words the keyboard inserts at once (by sliding across the keys, for example) go to the shell immediately, as one write that leaves an armed **Ctrl** or **Alt** for the next key.
- The keyboard's mic dictates into the shell as you speak. iOS keeps revising its guess, and each revision reaches the shell at once: one backspace per character back to the first one it changed, then the new text. When you tap the mic to stop, iOS's final text replaces the guess the same way. Oppi tracks what the keyboard typed since the last arrow, paste, tap, Return, or hardware key; a revision of text from before one of those is dropped.
- Text the keyboard hands over in one piece, such as a dictated phrase, that contains a newline or a control character asks first, like a multi-line paste, and is then pasted as one block. Return alone is Enter. Writing Tools is off there.
- On the terminal keyboard's bar, **Alt** then Return sends Alt+Enter (the same as Option-Return below). There is no Shift key on the bar, so Shift-Return needs a hardware keyboard.

### Hardware keyboard

While typing in the terminal (not the chat bar), a hardware keyboard adds these. Hold ⌘ to see ⌘C and ⌘K in the shortcut overlay.

| Keys | What happens |
|---|---|
| ⌘C | Copies the highlighted selection, with the same **Copied N characters** note as a touch selection: during a touch-and-hold drag, or while a double-tapped word or a released selection is still highlighted. With nothing highlighted it does nothing and sends nothing. |
| ⌘K | Clears like Ghostty's ⌘K. Local history is deleted. At a shell prompt the shell reported with OSC 133, the screen is cleared and a form feed (Ctrl-L) is sent so the shell redraws its prompt. Elsewhere the rows above the cursor are removed, the cursor's row moves to the top, and nothing is sent. On the alternate screen (vim, less, a TUI) ⌘K does nothing. |
| ⌘. | Esc. iOS turns ⌘. into Esc for every app, so it is not in the overlay. |
| ⌘V | Paste, with the same confirmation as **Paste**. |
| Option | Meta: Option with a key sends Alt with that key, as Ghostty does with `macos-option-as-alt = true`. In a shell Option-B and Option-F move by word. Option with Shift works with letters only; Option-Shift with another key sends nothing, since iOS does not report which shifted character it would be. Option does not type the characters a Mac layout puts on it (∫, é, or @ on some layouts). |
| Shift-Return | Shift+Enter: `ESC [ 27 ; 2 ; 13 ~`, or `ESC [ 13 ; 2 u` when the app turned on the Kitty keyboard protocol. pi reads it as a new line without sending. |
| Option-Return | Alt+Enter: `ESC` then Return, or `ESC [ 13 ; 3 u` with the Kitty keyboard protocol. pi reads it as a queued follow-up message. |

Other keys, including other ⌘ shortcuts, are sent as before.
- With the keyboard hidden, a tap starts typing: into the terminal when that is the input (a shell, or after the keyboard button or **Type in Terminal**), even if the app asked for mouse input; into the input bar for an agent.
- While the direct keyboard is up and an app asks for mouse input (Herdr, tmux with `mouse on`, many TUIs), a tap is a click at the cell and the keyboard stays up. Hide that keyboard with ⌄ on its bar. A tap hides the keyboard only when the app did not ask for mouse input.
- While the chat bar is the input and an app asks for mouse input, that tap is a click at the cell.
- A tap on the grid waits a moment before hiding the keyboard, so a second tap can copy. The ⌄ key hides it at once. Double-tap a word to copy it: the first tap still runs (opens the keyboard, or clicks in a mouse app), and the second tap only copies the word that was under the finger on the first tap. It does not hide the keyboard or send a click. Paths such as `/usr/local/bin/thing` and URLs such as `https://example.com/a/b?x=1` count as one word. A trailing colon is dropped (`src/x.swift:42:` copies `src/x.swift:42`, `error:` copies `error`) unless the word is a URL with a port or an IPv6 address. The word highlights briefly and **Copied N characters** appears. That copy is yours: it goes on this device's clipboard and is not OSC 52, so it is allowed even when a remote clipboard write would be dropped.
- Touch and hold, then lift without moving, opens the edit menu at the finger. Over an OSC 8 hyperlink, a URL, or a path, it offers **Open**, **Copy**, and **Paste**; a word with nothing to open offers **Copy** and **Paste**, and a blank cell keeps **Paste** alone. **Open** names where it goes, such as the site's host; a tap still types or clicks, and nothing about the hold reaches the host. See [Links, paths, and the shell's folder](#links-paths-and-the-shells-folder). **Paste** pastes as **Paste** on the bar does. An image (a screenshot, or a photo copied from Photos) is saved on the host like a chat-bar attachment, in that `oppi-ssh-<your uid>` folder, and its path is pasted, which Claude Code and pi read as the image. When the clipboard holds both text and an image, the text is pasted. **Paste** on the keyboard bar takes images the same way.
- Touch and hold, then drag, selects a range in a plain shell and copies it on release, with the same note. Selection never sends bytes to the host. In a mouse-reporting app the same gesture is a mouse drag (press, move, release) instead of a selection. A hold that has not moved yet sends nothing, so a mouse app gets no press or click from a hold that ends in **Paste**.
- Dragging a mouse-reporting app sends wheel steps. One wheel notch is three rows of finger travel, so Herdr (three lines per notch) tracks the finger. tmux (five lines per notch) runs a little ahead. The app moves whole lines, so a step goes out once the finger is halfway to the next one: the first notch comes a few points past a row and a half, and the text stays within about half a notch of the finger instead of trailing it. A small wobble back does not undo a step. A flick keeps going with the same native deceleration as local history; putting a finger down stops it and drops steps already queued. Wheel steps from one frame go in one SSH write, reported at the cell under the finger so a split-pane app (tmux, Herdr) scrolls the pane you flicked.
- On the alternate screen without mouse reporting (`less`, `man`, a git log pager, vim without mouse), a vertical drag sends ↑ and ↓, one per row of finger travel and timed the same way (the first a few points past half a row), with the same flick momentum and one write per frame. DEC 1007 (alternate scroll) is on by default, as in Ghostty. If the remote leaves that screen, or turns mouse reporting on or off, while a finger is still down or a flick is still coasting, that gesture is dropped: it does not type into the shell, does not send wheel steps, and does not jump local history. The next touch starts fresh.
- Otherwise, dragging reads local history. The text glides under the finger point for point, not a row at a time, and it starts moving with the finger's first few points of travel instead of after the system's drag threshold. A flick keeps native momentum and rubber-bands at the ends, and the scroll indicator is sized from the terminal's scrollbar. A scroll can stop partway through a row; the row below shows in the strip at the bottom, and a tap or selection there acts on that row. A drag released within half a row of the bottom is back at live. **Back to Live** returns to the bottom.
- The terminal has no navigation bar. **Back** (‹) is a small glass button at the bottom left. A second one at the bottom right holds the program-status symbol (while a program has reported), Herdr (when the host has it), the [terminal switcher](#switching-terminals) (while more than one terminal is open), and **…**. The bar ends just above the home indicator and the grid ends above the bar, so it never covers a terminal row. The … menu's header names the screen — the title the shell set, or the saved host — followed by the shell's folder when the shell reports one (OSC 7). Swiping from the left edge goes back too, as does VoiceOver's two-finger scrub.
- While a docked keyboard is up (the chat bar or typing in the terminal) the bar goes away and the grid takes its rows, in the same resize the keyboard already sends; it comes back when the keyboard goes down. Because the bar only takes rows while the keyboard is down, a connection that drops and reconnects with the keyboard up floats the bar over the grid's bottom rows instead of resizing the shell, so reconnecting never resizes it. Docked means on this display: iPhone, the Duo's inner screen, or iPad docked. A floating iPad keyboard leaves the bar, and so does a keyboard on the Duo's other display. When the chat bar is the input, the bar sits below the chat bar, so the order is always the grid, then the chat bar, then the bar. A broken connection keeps the bar, so Back and Reconnect stay in reach; with a keyboard up it then floats at the keyboard's top edge, and the grid ends above it. Swiping from the left edge goes back while the bar is gone. The remote shell resizes once per keyboard change.
- When Herdr or a blocked program wants you, an orange dot sits on Back. It goes away when the wait ends. VoiceOver reads **Attention pending** on Back.

A healthy connection shows no status banner. Connecting, disconnected, and network-changed copy, plus paste, open, and input warnings, float at the top edge of the grid. They do not change its size or resize the remote shell. **Edit Host**, **Disconnect**, and **Reconnect** are in the … menu.

## Links, paths, and the shell's folder

The terminal reads the folder the shell reports, OSC 7 `file://host/path`. A `file:` URL is the only form it accepts, so a bare path or another scheme leaves the folder unknown. The host in the URL names the machine the shell runs on: the first host a connection reports is the one that counts, and a report from a different machine (a nested `ssh`, a `tmux` session on another host) leaves the folder unknown rather than resolving this server's paths against someone else's. When the shell reports one, the **…** menu's header shows it after the screen's name.

Touching and holding a cell, then lifting without moving, opens a menu for that cell. A cell that is on an OSC 8 hyperlink, a URL, or a path offers **Open** and **Copy** beside **Paste**. A word with something to copy but nothing to open, such as a path on a host that is not a paired server, offers **Copy** and **Paste**. A blank cell keeps **Paste** alone. **Copy** takes the link when the cell carries one, so a blank or punctuation cell under a link offers **Open** and **Copy**; otherwise it takes the word. Words come from the same rules as a double tap, so `https://example.com/a/b?x=1` and `/usr/local/bin/thing` are one word. A trailing `:line` or `:line:column` is dropped for **Open** and kept for **Copy**, since the copy is what you paste into an editor; a URL is read whole, so its `:port` is never mistaken for a line number.

- **Open** on an `http` or `https` URL opens it in the browser chosen for links (Settings → General → **Open Links**: the In-App Browser by default, or the External Browser), and the item names the site so you see where the tap goes. Other schemes (`mailto:`, `vscode:`, `ftp:`) are not opened; they can be copied. An OSC 8 link wins over the text it covers, and a link with another scheme is not replaced by the word it covers.
- **Open** on a path opens the file in Oppi's own viewer when this SSH host is also a paired Oppi server: the host and the server's host must name the same machine, including a tailnet name and its short name (`mac-studio` and `mac-studio.tail1234.ts.net`). Two paired servers that could both be that machine (`mac-studio.a1.ts.net` and `mac-studio.b2.ts.net` for `mac-studio`) match neither, so the terminal does not guess. A relative path resolves against the shell's folder; with no folder reported, a relative path can only be copied. A folder opens the Files browser at that folder instead of the viewer.
- Owner-host files are rooted at the user's home folder on the server, so a path outside it is not offered: no **Open** for it, only **Copy**. A host that is not a paired server offers **Copy** for paths, never **Open**.

Each Open and **Browse Files Here** replaces the one before it, and leaving the terminal while one is looking up its file pushes nothing.

**Browse Files Here** in the **…** menu opens the Files browser at the shell's folder, when the shell reported one and the host is a paired server. The menu's **Open** for a path needs the same pairing; the file, the folder, and the browser are all read through that server, not over SSH.

## Herdr

When `herdr` is on the host, the terminal checks Herdr's API (`herdr api snapshot`) every few seconds over the same SSH connection, in a separate command channel. A grid button appears beside **…** at the bottom right, orange while agents wait at an approval or question prompt. It opens a list of workspaces and agents. Each agent shows the same status symbol and label as the program-status glyph: Working (animated), Question, Done, or Idle. The focused workspace and agent are bold. Herdr decides the state from the agent's screen or its Herdr integration, and does not pass OSC 7501 through to this terminal. A Herdr version that lists a pane's OSC 7501 records in its API (`program_status`) is read the same way as records in a plain terminal: the records lead, a child's wait counts, and the blocked kind shows (Needs approval, Sign-in, Question). Without records, Herdr does not say which kind of wait it is, so a blocked agent reads as Question. Done means Herdr saw the agent go idle and nobody has looked yet, so a question Herdr does not recognize shows as Done. Oppi's `ask` extension tells Herdr's Pi integration when it waits, so a pi question reads as Question. An unrecognized Herdr state shows as Unknown. Tapping a row runs `herdr workspace focus` or `herdr agent focus` on the host, which moves the Herdr session's focus for every client attached to it. Hosts without `herdr` are checked once per connection and then left alone. **Open Terminal here** on a host whose Run on Connect command is `herdr` uses the same snapshot: a workspace with a pane in the folder is focused, and one is created when there is none.

## Clipboard

When a program on the host copies text to the terminal's clipboard (OSC 52), the text goes on this device's clipboard and a short **Copied N characters** note appears over the terminal. Herdr forwards a pane's copy this way (copy-on-select, an agent's `/copy`), as does tmux with `set-clipboard on`. Only UTF-8 text of up to 1 MB, sent to the standard clipboard (`c`), is copied. Requests to clear the clipboard and writes to the X11 selection or primary buffer are ignored. Copying is write-only: the host can never read this device's clipboard, and clipboard queries get no reply. Oppi applies a remote copy only while that terminal's screen is showing and Oppi is in front; a terminal you left, or Oppi in the background, drops it. A double-tap or a long-press selection copy is your own action, not OSC 52, so it is allowed regardless of that gate. Paste is always your action, through **Paste** or ⌘V.

## Program status (OSC 7501)

The terminal answers the Program Status Protocol support query (`ESC ] 7501 ; ? ST`) with the revision 0.4 reply, which lists the states and kinds it accepts (`?:states=idle,working,done,blocked,error:kinds=permission,question,auth`), so programs that detect support first, such as Pi 1.1.0, start reporting. Reports (idle, working, done, blocked, error, with an optional app, title, and message) are kept per terminal following the [specification](https://www.superlogical.com/rex/docs/build/program-status): one record per id, a `clear` removes a record and its children, at most 256 records. `working` and `blocked` records are dropped when the shell shows its next prompt (OSC 133 A) or the shell or connection ends; `done` and `error` stay. Reset (RIS) clears everything. This reply is the only OSC reply the terminal sends; clipboard queries still get none.

While a program has reported, the top-right controls show a status symbol, not a word: a blue progress mark while working, an orange hand, question, or lock while blocked, and a grey dot at rest. Tap it for the list of programs, with this host named at the top. Done and Error show in green and red only until this terminal is on screen; looking at the terminal counts as seen, so a just-finished run holds its colour briefly and then settles to Idle. A record tree uses the same roll-up as a thread: a blocked record wins over a working root. Nothing shows until a program reports.

When any record is blocked, a card floats over the top of the terminal. It names the kind, the saved host, and the program's message. It does not change the terminal's size, and it is not a dialog: you answer in the terminal or the chat bar. If it covers the program's own prompt, tap it or swipe it up (VoiceOver: the Dismiss action); it folds into the status symbol, which stays orange and still lists the message. It stays away while the program repeats the same report, and comes back for a different kind of wait, the next time the program blocks, or a new message once the program's reports pause for a second (a message rewritten in a loop updates the card's text without bringing it back).

## Progress (OSC 9;4)

A program can report progress with OSC 9;4 (`ESC ] 9 ; 4 ; state ; percent ST`, ConEmu and Windows Terminal; cargo, `brew`, `winget`, and `systemd` tools send it). The status glyph in the bottom bar draws it as a ring around its symbol:

| Report | Ring |
|---|---|
| `1;N` set | Blue, filled clockwise from the top to N%. |
| `3` indeterminate | Blue, a short arc that spins. |
| `2` or `2;N` error | Red, filled to N%; with no number, a full ring, still (the work stopped; it is not going on). |
| `4` or `4;N` pause | Orange and dashed, filled to N%; with no number, a full ring. |
| `0` remove | No ring. |

The ring composes with [program status](#program-status-osc-7501): when a program has also reported OSC 7501, its status symbol stays in the middle and the ring goes around it. With progress alone, the ring is the whole glyph. It is then not a button, since there is no program list to open; tapping does nothing. VoiceOver reads the value as **Progress 40%** (also **Progress paused at 60%**, **Progress failed**, **Progress, in progress**), after the status when there is one. With **Reduce Motion** on, nothing spins: an indeterminate report is a dotted full ring.

Each report replaces the one before it. A report that is not renewed for 15 seconds goes away, as it does in Ghostty, since a program that was killed never sends the remove. Every new report, even an identical one, restarts those 15 seconds. A reset (RIS) and the end of the connection clear it too. Progress is not a notification: no card and no haptic.

## Notifications and the bell

A program can notify the terminal with OSC 9 (`ESC ] 9 ; text ST`, iTerm2) or OSC 777 (`ESC ] 777 ; notify ; title ; body ST`, rxvt and Ghostty). The same card shows it, headed **Notification**, with the program's title and text on their own line, and leaves after six seconds or when you tap it. Notifications less than a second apart are one notification whose text updates, so a program printing them in a loop cannot hold the card up or bring it back. A blocked program comes first: while its card shows, a notification waits behind it, and folding one card away never brings back the other. A new card of either kind gives a warning haptic, at most once a second. OSC 9;4 progress reports are not notifications; they draw [a ring](#progress-osc-94). A bell (BEL) gives a light haptic and no card, since shells ring it for ordinary things such as a failed completion; bells within one second count once.

The terminal hears these while its connection is open, including after you leave its screen ([Keeping a terminal open](#keeping-a-terminal-open)); it hears nothing once the connection has closed. Programs inside Herdr usually notify Herdr, not this terminal, and Herdr's own notifications use Kitty's OSC 99, which the terminal does not read yet.

## Credentials and host trust

- Profile metadata (host, port, username, sign-in choice, and Run on Connect) is stored in app preferences. Passwords are never stored there or logged. Each saved host has its own id. Changing that host’s hostname, port, username, or sign-in method cannot keep its password, and does not change another host’s password.
- An unsaved password is used for one connection attempt. Reconnect asks for it again.
- A saved password is in the app’s private Keychain, not the app group. It does not sync or migrate to another device. A device passcode is required to save it; reading it at connect requires Face ID, Touch ID, or device-passcode approval, which Oppi [reuses for 5 minutes](#approval-reuse). The saved secret is bound to that host’s id, so copying one host’s secret onto another host’s item does not sign in.
- On a physical device, the per-device P-256 SSH key is in the Secure Enclave. Signing requires user presence, reused for 5 minutes ([Approval reuse](#approval-reuse)). The simulator uses an explicitly labelled software key. Selecting password sign-in does not create a key.
- Trusted host keys are stored in the app-private, this-device-only Keychain, shared by SSH Terminal and Check a Machine. A changed host key blocks sign-in. **Forget Trusted Key** requires confirmation; independently verify why it changed before trusting its replacement.
- **Delete Host**, including swipe delete on the list, deletes that saved host and its saved password. It does not remove the per-device key or trusted host keys. Trusted host keys stay keyed by host and port. The device key stays one per device. If the host list cannot be read, saving is blocked until **Reset Host List** removes the unreadable list; add the hosts again after that. Reset does not search the Keychain.

## Keeping a terminal open

While Oppi is in the foreground, a connected terminal stays connected when you leave its screen: Back, another tab, another session. Tap that host in the list again (it reads **Connected**) and you get the same live channel and grid, with no reconnect and no sign-in. Oppi keeps one terminal per saved host and folder, so at most as many as you have saved hosts plus folders you opened. Connecting an identity that already has one shows that terminal; **Reconnect** and a connect after the shell ended open a new one.

A terminal ends when you tap **Disconnect**, when the remote shell or command exits or the connection drops, when you save changes to the host or delete it, or when the [background grace](#network-and-reconnect) ends. Saving the host without changing anything keeps it.

While a terminal is off screen Oppi still reads its output and answers its terminal queries, and checks the connection after a network change. The Herdr list and program shortcuts load again when you return.

### Switching terminals

With more than one terminal open, a **Switch terminal** button (stacked rectangles) sits beside **…** in the bottom bar. It opens a menu of every open terminal: each host's own terminal and each folder terminal, as the saved host (`user@host`) over the folder's last component (`oppi` for `~/workspace/oppi`), or over the host's Run on Connect command or **Login shell** for its own terminal. A green dot marks a connected terminal; a terminal whose program is blocked and waiting for you shows that program-status symbol instead and says what it waits on. The terminal on screen is checked, and the list keeps one order: hosts by name, a host's own terminal first, then its folders.

Choosing one swaps the screen to that terminal, with the same live channel and grid as tapping its **Connected** host in the list: nothing dials, nothing signs in, and the terminal you left stays open and keeps reading its output. **Reconnect** and **Edit Host** then act on the terminal now shown, from whichever screen opened this one (the host list, a folder's connecting screen, or the Add/Edit Host form): a Reconnect that needs a password asks for that terminal's host, names it in the sheet, and its **Save Password** switch edits that host; a host-key prompt is for it too, and the folder and attach command it reopens are its own. **Edit Host** opens that host's form. What you were typing in the chat bar stays with its terminal: swap away and back and the text and attachments are there again (until you leave the terminal screen). The button is hidden with one terminal open, and returns when a second one opens. VoiceOver reads **Switch terminal** with the count open.

## Approval reuse

Face ID, Touch ID, or the passcode is asked when a sign-in needs your device key or a saved password. Oppi remembers that approval for 5 minutes, separately for the device key and for each host's saved password, so a reconnect in that window (**Reconnect**, or the automatic one on return) does not ask again. Oppi keeps its own approval for this; it does not widen the system's biometric reuse. The approval ends early when the 5 minutes pass, when App Lock locks or covers Oppi, and on any sign-in or approval failure; the next sign-in asks again. Approvals are never saved to disk, and a terminal that is already connected does not depend on them.

## Network and reconnect

When Oppi’s in-app Tailscale node is running, tailnet names (`*.ts.net` or `*.beta.tailscale.net`, with or without a trailing dot) use that node. Other hosts, and tailnet names while that node is stopped, use direct TCP through your current network, including a system Tailscale VPN if active.

Oppi checks SSH round-trip liveness every 60 seconds by opening and closing an empty session channel, with a 15-second reply timeout. It requests no shell, command, or PTY on that probe. Direct TCP also uses kernel keepalive probes. Failure closes the connection and shows **Disconnected** with **Reconnect**.

Entering the background keeps the shell running for about 25 seconds, still reading its output, under an iOS background task. Return within that time and nothing reconnects. A connect or reconnect still signing in or dialing when Oppi goes to the background is cancelled, and one that finishes there is closed again, so no session is left for iOS to suspend; a terminal screen you were on reconnects when you return. Otherwise Oppi closes the connection before iOS can suspend it (also if iOS ends the background task earlier), with the reason **Oppi went to the background.** Closing is deliberate: a suspended app would silently lose the bytes the host sends. When you return, a terminal that was on screen reconnects on its own, signing in like **Reconnect** (see [Approval reuse](#approval-reuse)); with App Lock on, after you unlock. A terminal you had already left is not reconnected. If that sign-in is cancelled or fails, the terminal shows **Disconnected** with **Reconnect**. After a Wi-Fi or cellular path change, Oppi checks the connection with one SSH round trip: a live shell carries on, and a dead one shows **Disconnected** with **Reconnect**. Those notices float over the grid and do not resize it. Reconnect always opens a fresh shell; it does not replay input. Use `tmux` on the host if work must survive a disconnect.

## Limits

- Hosts are saved on this device only. No private-key import, keyboard-interactive, or forwarding.
- Images use the direct transmission medium only, and Unicode-placeholder (tmux) images do not draw yet; see [Images](#images).
- The SSH library supports Ed25519/ECDSA host and user keys, Curve25519/ECDH key exchange, and AES-GCM encryption. RSA-only and legacy-only servers fail with an unsupported-algorithm error. A server that offers only keyboard-interactive cannot accept password sign-in here.
- Connection, authentication, and terminal-opening waits are bounded. A rejected credential, changed host key, unreachable host, or unsupported algorithm produces a visible error.
- Secure Enclave and biometric approval need physical-device testing. A simulator software key is not evidence of hardware protection.
