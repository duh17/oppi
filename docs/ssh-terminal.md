# Terminal

The Terminal tab opens an interactive shell on a host saved on this iPhone or iPad. It connects straight from the device, not through the Oppi server, and does not change Pi session ownership.

## Set up a host

1. Open **Settings → Terminal**, or **Terminal** below **MCP Servers** in the workspace sidebar. Opening the list does not ask for Face ID or show a prompt by itself. With a saved [Rex host](#rex-sessions-on-the-terminal-tab) (or a host Oppi has seen Rex on) it checks the Keychain for a trusted host key and signs in to read that host's Rex sessions only when nothing would ask for a password, a trust decision, or Face ID (a saved password or device key you approved in the last 5 minutes counts); otherwise the host shows **Tap to connect**.
2. Tap **Add**. Enter a host, port (default 22), and username. The host has no default. Enable Remote Login or `sshd` on it. **Edit** reopens the form for a saved host.
3. Choose **Password** or **This Device's Key**.
   - **Password:** enter it at connect. **Save Password** is optional.
   - **This Device's Key:** copy the public key and add it as one line to `~/.ssh/authorized_keys` on the host; Oppi does not install it. A **Sudo Password** is optional, for [Fill Password](#filling-a-password).
4. Tap **Connect**. Compare the displayed host-key fingerprint with the host's through an independent channel, and trust it only if they match. Oppi sends no credentials before host-key validation succeeds. You can also tap **Save Host** and connect later.

For a Mac with an Ed25519 host key, `ssh-keygen -lf /etc/ssh/ssh_host_ed25519_key.pub` prints the fingerprint.

The Terminal tab leads with **Add Host** when no host is saved, and with a [Rex section](#rex-sessions-on-the-terminal-tab) when a saved host uses Rex or Oppi has seen Rex on it. A row shows `user@host`, the port when it is not 22, the Run on Connect command, **Login shell**, or **Rex sessions** for a [Rex host](#a-rex-host), and each folder a terminal is open in. Two rows can use the same machine with different Run on Connect commands. Swipe **Delete Host** removes that host and its saved passwords only. **Edit Host** in a live terminal opens the form for the connected host. **Tailscale → Set Up a Mac or Linux Computer** is a separate screen.

## Run on Connect

**Run on Connect** runs one command instead of a login shell, as `ssh -t host 'command'` does. The connection ends when the command exits, and **Reconnect** runs it again. The command must be on the `PATH` that non-interactive SSH commands see. Leave it empty for a login shell.

**Multiplexer**, above it, picks one for you: **Herdr** sets Run on Connect to `herdr` and **tmux** to `tmux new -A -s main` (a command that already starts that multiplexer, flags and all, is kept), and **None** clears a multiplexer's command but keeps any other program. Typing a command updates the choice. **Rex** is different: Rex is not run in the host's terminal, so Run on Connect is hidden and cleared, and connecting opens the host's [Rex sessions](#a-rex-host) instead of a terminal.

## Open Terminal here

A workspace's **Terminal** button (top right, beside **Config**) and a chat's **Terminal** button open a folder on the saved host that serves the workspace's server:

- from a workspace: its root folder;
- from a chat: the session's own worktree when it has one, else the workspace root. If the chat's worktree cannot be looked up (the server is disconnected or no longer lists it), the chat shows **Cannot Open Terminal** with the reason instead of opening a folder it never ran in.

The host's Run on Connect command decides where the folder opens, by its first word (a path such as `/Users/you/.local/bin/herdr` counts):

| First word | Where the folder opens |
|---|---|
| `herdr` | Inside the Herdr session the host's own terminal already runs |
| `tmux` | A terminal of its own, attached to that folder's tmux session |
| anything else, or none | A login shell in the folder |

- **Herdr:** Oppi asks Herdr, over that terminal's side channel, to show the folder; nothing is typed into Herdr. If a Herdr workspace already has a pane in the folder (symlinked spellings such as macOS `/tmp` count as the same), Oppi focuses it. Otherwise it creates a workspace there, or for a chat in a git worktree opens that checkout as a Herdr worktree, labelled with the Oppi workspace (and worktree name). Focusing moves the Herdr session's focus for every client attached. If Herdr is not running or refuses, a notice offers **Retry** and leaves you in the Herdr terminal; start Herdr there, then Retry opens the folder without reconnecting.
- **tmux:** the terminal enters the folder, then runs `tmux new -A -s <session>`, which creates the session the first time and attaches it afterwards, so it survives a disconnect. A missing folder is reported rather than opening a session elsewhere. The session is named after the workspace (and worktree) plus a short hash of the folder, so same-named workspaces never share a session; `.` and `:` become `-`.
- **Anything else:** a login shell in the folder that ignores Run on Connect and never types into a program the host already runs. The host list's row still opens the host's own shell or command.

Server-supplied values (folder, workspace name, worktree name) reach the host as octal-escaped bytes in one quoted command word, so none is read as shell code, and spaces, quotes, `$`, backticks, newlines, and non-ASCII all work. A `~` folder expands to the host's home. A missing folder prints `oppi: /that/path: no such folder` and ends. A sandbox workspace, or one whose folder is relative to the server's working directory, offers no Terminal.

Oppi picks the host by matching the workspace's server host against saved hosts, ignoring case and a trailing dot, and treating a tailnet short name (`mac-studio`) and full name (`mac-studio.tail1234.ts.net`) as one machine. An exact address match comes first, then a short-name match. Among matches, a host whose command starts a multiplexer (`herdr`, `tmux`) wins over a host with no command, then any other, then the first saved, so a machine saved twice still opens the folder inside Herdr. With no match, **Add Host** opens with the server's host filled in.

A folder terminal is kept while connected: leaving the workspace or chat keeps it, and tapping Terminal again returns to the same shell. Oppi keeps one terminal per saved host and folder; under Herdr there is one client per host that shows whichever folder you last asked for. Editing or deleting the host ends them, and so does the background grace ([Network and reconnect](#network-and-reconnect)). Which chat top-bar buttons show, and why Terminal can be missing, is in [Using Oppi](usage.md#chat-display).

## Font, icons, and colors

The terminal uses **Settings → Text → Code Font** and **Code Text Size** (13 pt at 100%). Changing either redraws an open terminal and resizes the remote shell. Prompt icons from starship, powerlevel10k, oh-my-posh, and similar come from the bundled Nerd Fonts Symbols font.

### Colors

The terminal takes its colors from the host's [Ghostty](https://ghostty.org) theme. Each connect, Oppi reads the host's Ghostty config over the connection's side channel and paints with it. A host without Ghostty or a config keeps Oppi's theme. Nothing else is read:

- `theme`: a name, an absolute path, or `light:X,dark:Y` (the side matching Oppi's appearance). A name is looked up in `$XDG_CONFIG_HOME/ghostty/themes` (default `~/.config/ghostty/themes`), then `$GHOSTTY_RESOURCES_DIR/themes`, the macOS app's resources, and `/usr/share/ghostty/themes` and `/usr/local/share/ghostty/themes` on Linux.
- `palette = N=#rrggbb`, `background`, `foreground`, `cursor-color`, `selection-background`. Colors are `#rrggbb` or `#rgb`, with or without `#`; color names and `cell-foreground` are not read.
- Config files: `$XDG_CONFIG_HOME/ghostty/config` and `config.ghostty`, plus the same two under `~/Library/Application Support/com.mitchellh.ghostty` on macOS. A `config-file` line is followed one level deep.

As in Ghostty, values in the config win over the theme file's entry by entry, and later lines win. Fonts, size, opacity, blur, and keybinds are ignored. Colors apply to the default foreground and background, any of the 256 palette entries the theme or config sets, the cursor, and the selection highlight. The bottom bar, buttons, and key strip follow the terminal background, and the screen switches to light or dark chrome by that background, clock and battery included. The input bar, banners, and notices use your Oppi theme when it is on the same side, and Oppi's built-in Light or Dark otherwise, so text stays readable. A program's own OSC 4, 10, and 11 changes still apply. `cursor-text`, `selection-foreground`, and `background-opacity` are not read or applied.

Each file is cut at 64 KB and the whole read at 256 KB, and parsing happens on this device. Oppi keeps the last theme read per host, so the next connect paints at once and then refreshes. If the host changes its theme while a terminal is open, reconnect to pick it up; switching Oppi between light and dark rereads a `light:`/`dark:` pair.

**Terminal Colors** in the host form chooses the source per host:

| Choice | Result |
|---|---|
| Host's Ghostty theme (default) | The theme above. The row shows the name last read, such as `tokyonight`, or `not found`. |
| Oppi theme | Oppi's own colors; nothing is read. |
| A named theme | One theme from the host's theme folders instead of its config. |

The named-theme list comes from the host when the picker opens, so it needs an open terminal for that host (open the form from the terminal's **…** menu, **Edit Host**). Otherwise the picker offers the first two choices and the one already chosen. The choice applies to an open terminal at once without ending it or asking you to sign in again.

## Images

The terminal draws images sent with the [Kitty graphics protocol](https://sw.kovidgoyal.net/kitty/graphics-protocol/), so `kitten icat`, chafa, timg, `viu`, Yazi previews, and an agent's image output appear in the grid. A program that asks whether images are supported (`a=q`, as `kitten icat` does first) is told yes.

- **Accepted:** images sent inside the escape code (direct `t=d` medium) as RGBA, RGB, zlib-compressed, or PNG data. PNG is decoded on this device with ImageIO, and only PNG; anything marked PNG without the PNG signature is refused with `EINVAL: invalid data`. The file, temporary-file, and shared-memory mediums are refused with `EINVAL: unsupported medium`, so a host over SSH can never make this app open a local file.
- **Limits:** each screen keeps up to 64 MB of decoded images, dropping the oldest, and an image over the limit is rejected. A PNG over 64 MB or 10000 pixels a side is refused from its header. A frame draws at most 256 images and 1024 placements. A hostile image can briefly push memory use to about 1.1–1.2 GB while it arrives, which may end the app on a device short of memory; this is a known limit of the bundled libghostty.
- **Placement:** images draw at their cell, honoring the source rectangle, size, aspect ratio, and z-index (negative z under the text, below −1073741824 under the cell background too, otherwise over the text), clipped to the grid, and scroll with history. Delete (`a=d`), retransmission of the same id, and reset (RIS) replace or remove the picture.
- **Not drawn yet:** the Unicode-placeholder form (`U=1` virtual placements, used to show images through tmux). Those cells stay blank, so `kitten icat` shows nothing inside tmux and works outside it.

## Input bar, touch, and keyboard

The terminal opens with direct typing and shows the chat input bar only when you ask for it. Tap the bottom bar's **Chat Bar** (💬), or the chat button on the terminal keyboard's bar; **Type in Terminal** (⌨) goes back to direct typing, and the button for the input in use draws filled. A program's report never brings the chat bar up or takes it away, whether it is a coding agent, a shell, `vim`, `tmux`, or Herdr. A tap on the terminal never starts typing. Your choice lasts while you stay on that terminal: going back, switching to another terminal, opening a Rex pane, or reconnecting starts over in direct typing. The chat bar is hidden while the terminal's own keyboard is up (the bar's keyboard button), and a password prompt moves typing to the terminal until it ends, then back to the chat bar.

The key strips still follow the program. Oppi does not inspect host processes; a program that reports [OSC 7501](#program-status-osc-7501) on the root as a coding agent gets that agent's keys (such as Thinking and Model) on the keyboard bar and the chat bar's key strip, and anything else (a shell, `vim`, `tmux`, a program that does not report, a cleared root, or a report from before the shell's latest prompt, OSC 133) gets the shell's. Agent ids are `pi`, `claude`, `codex`, `opencode`, `gemini`, `amp`, `aider`, `goose`, `crush`, `droid`, `cursor-agent`, `qwen`, `kimi`, `copilot`, `kilo`, and `grok`, also with a suffix such as `claude-code`. Agents that do not report yet (OpenCode, Copilot CLI, Gemini CLI, and others) get the shell's keys, and so does Herdr, whatever its panes run: Herdr does not pass its panes' reports through.

**Chat input bar.** Oppi's chat composer: type or dictate, edit, then **Send**. Oppi pastes the text as one block (bracketed paste when supported) and presses Enter; Send on an empty bar presses Enter alone. Autocorrect, capitals, and smart punctuation are off. While focused, a key strip offers the program's keys (such as Thinking and Model), the arrows, then Esc, Tab, Ctrl-C, and Ctrl-D in one row; swipe for keys that do not fit. The keyboard button at its right end switches to typing straight into the terminal. The bar grows over the terminal rather than shrinking it, so the remote shell is not resized while you compose and the program does not redraw; the picture shifts up by the fewest whole rows that keep the program's cursor row above the bar, and returns when it shrinks. The remote terminal resizes when the keyboard appears or goes away, on rotation, and when the bar appears or goes.

**Terminal keyboard.** A two-row bar: Esc, Ctrl, Alt, Tab, and the arrows, then Paste and the program's keys. Swipe either row to reach keys that do not fit; both move together. The chat button and ⌄ (hide keyboard) stay pinned at the right end. **Type in Terminal** on the bottom bar opens it; a tap on the terminal does not. While it is up and the app asked for mouse input (Herdr, tmux with `mouse on`, many TUIs), a tap is a click at the cell and the keyboard stays; hide it with ⌄. Otherwise a tap hides it, after a short wait so a second tap can copy.

### Program shortcuts

The key strip and the terminal keyboard add buttons for the agent that reports itself (or the shell), named by what they do. Each sends the key the program has bound now:

| Program | Buttons (default key) | User file read |
|---|---|---|
| Shell | History (^R), Clear (^L) | none |
| pi | Thinking (⇧Tab), Model (^L), Tools (^O); Stop when interrupt is not Esc | `${PI_CODING_AGENT_DIR:-~/.pi/agent}/keybindings.json` |
| Claude Code | Mode (⇧Tab), Model (⌥P), Transcript (^O), Todos (^T), Background (^B) | `${CLAUDE_CONFIG_DIR:-~/.claude}/keybindings.json`, contexts Global, Chat, Task |
| Codex | Transcript (^T), Effort − (⌥,), Effort + (⌥.); Stop when interrupt is not Esc | `[tui.keymap.*]` in `${CODEX_HOME:-~/.codex}/config.toml` |

The file is read once whenever the program changes, through a side command on the same connection, and follows that program's rules: pi and Codex entries replace an action's keys (`[]` removes it), and Claude Code entries add keys (a default key bound to `null` or another action stops counting). A missing or unreadable file means defaults. For Codex only the `tui` tables leave the host, and only table headers, dotted keys, and string arrays are read. The variables are those of a non-interactive SSH command, which may differ from the agent's. Actions bound to Esc, ^C, Tab, ↑ or ↓ are not repeated, `super` and `cmd` keys are left out, and Claude Code chords go as one write. Other agents get fixed keys only. Under Herdr the buttons are the shell's.

### Attachments and secure input

Photos and files from **+**, and a pasted image, are saved on the host before Send in an owner-only (`700`) `oppi-ssh-<your uid>` folder under `$TMPDIR` (or `/tmp` without one) over the same SSH connection. The prompt then lists each file's path on its own line so the agent can read it. Each file is limited to 32 MB. The save is refused, with the reason shown instead of the path, when that folder is a symlink, not a directory, or owned by another user. On a shared `/tmp`, another local user could create that folder first to block your uploads, and they then fail with that reason rather than writing anywhere unsafe. Oppi never deletes these files; the host's temporary-folder cleanup does.

A password prompt on screen turns on the keyboard's secure entry, and the bar shows **Secure Input** with a lock. Third-party keyboards, dictation, and keyboard learning then do not see what is typed. Oppi recognizes the prompt from the cursor's own line on the live screen, so it works for `sudo`, `su`, `ssh`, and `ssh-agent`, in a shell or a Herdr pane, and typing `echo Password:` does not trigger it. It stays on while the secret is typed (including echoed `*`) and ends when the cursor leaves the line, not when you read history. If the chat bar was the input, typing moves to the terminal until the prompt ends, then back. Two painted frames of new output must agree before it ends, so rotating or showing the keyboard does not end it early. A password is never typed into the chat bar's draft. With a saved password, the bar also offers [Fill Password](#filling-a-password).

### Touch

- **Delete:** holding ⌫ repeats; after about a second each repeat deletes a word (Ctrl-W) instead of a character, only on the normal screen. Full-screen apps on the alternate screen (vim, nano, less, Emacs) keep getting ⌫.
- **Space-bar trackpad:** touch and hold the space bar, then slide, to move the cursor one ← or → per cell and one ↑ or ↓ per row. In a shell, ↑ and ↓ walk history. It moves nothing while a keyboard such as Japanese is composing.
- **Dictation:** the keyboard's mic dictates into the shell as you speak. Each revision reaches the shell at once (backspaces to the first changed character, then the new text); revisions of text from before an arrow, paste, tap, Return, or hardware key are dropped.
- **Text handed over in one piece** (a dictated phrase, sliding across keys) goes to the shell at once and leaves an armed Ctrl or Alt for the next key. Text with a newline or control character asks first, like a multi-line paste. On the terminal keyboard, **Alt** then Return sends Alt+Enter; Shift-Return needs a hardware keyboard.
- **Double-tap a word** to copy it. The first tap still runs (a click, or hiding the keyboard), and the second only copies the word under the first. Paths and URLs count as one word, a trailing colon is dropped (`src/x.swift:42:` copies `src/x.swift:42`) unless the word is a URL with a port or an IPv6 address. **Copied N characters** appears. This copy is yours, not OSC 52.
- **Touch and hold, then lift** without moving opens an edit menu at the finger: **Open**, **Copy Link**, **Copy**, and **Paste** where they apply ([Links, paths, and the shell's folder](#links-paths-and-the-shells-folder)). **Paste** saves a clipboard image to the host like a chat-bar attachment and pastes its path (text wins when both are present); the keyboard bar's **Paste** does the same.
- **Touch and hold, then drag** selects a range in a plain shell and copies it on release. Selection never sends bytes to the host. In a mouse-reporting app the same gesture is a mouse drag, and a hold that has not moved sends nothing.
- **Scrolling:** in a mouse-reporting app a drag sends wheel steps, three rows of finger travel per notch, at the cell under the finger so split panes scroll the pane you flicked, in one SSH write per frame. On the alternate screen without mouse reporting (`less`, `man`, a pager, vim without mouse), a vertical drag sends ↑ and ↓ per row (DEC 1007 alternate scroll, on by default as in Ghostty). If the remote changes screens or mouse reporting mid-gesture, the gesture is dropped. Otherwise a drag reads local history with native momentum and rubber-banding. A drag released within half a row of the bottom is back at live, and the glass arrow button at the bottom trailing corner (**Back to Live** to VoiceOver, the same button the chat timeline uses to jump to the latest message) returns there.
- **Back and bar:** the terminal has no navigation bar. **Back** (‹) is a small glass button at the bottom left, and swiping from the left edge goes back too. The middle holds **Type in Terminal** and **Chat Bar**. A bar at the bottom right holds the program-status symbol, Herdr and Rex (each when the host has it), the [terminal switcher](#switching-terminals) (with more than one terminal open), and **…**. **Settings → Terminal → Bottom Bar**, also **Customize Bar…** at the end of the **…** menu, turns buttons on or off and drags them into order: the middle can also hold Esc, Ctrl-C, Tab, ↑, ↓, Return (sent without opening the keyboard), Paste, and Browse Files Here, and the right side's Herdr, Rex, and switcher can be hidden or swapped. A button turned off moves into the **…** menu, except keys and Paste (the keyboard bars and the hold menu have them). A middle button that does not fit the screen's width moves there too, except Paste, which is left out until there is room. The layout is kept on this device, the same for every host. The **…** menu's header names the screen (the shell's title or the saved host) and the shell's folder when it reports one (OSC 7). While a docked keyboard is up the bar goes away and the grid takes its rows, and it returns when the keyboard goes down. Herdr and Rex are never both offered in one terminal: a [Rex pane](#opening-a-rex-pane) has Rex and no Herdr, and a terminal that Run on Connect started in Herdr (`herdr`, a path to it, or with arguments; not a `herdr` typed into a shell) has Herdr and no Rex, in the bar, the **…** menu, and **Customize Bar…** opened from that terminal. A plain shell on a host with both keeps both, and **Customize Bar…** from Settings lists every button. The other multiplexer is only hidden: the saved layout is not changed, and a plain shell shows it again as you left it. A broken connection keeps the bar so Back and Reconnect stay in reach. An orange dot on Back means Herdr, Rex, or a blocked program wants you (VoiceOver: **Attention pending**).

A healthy connection shows no banner. Connecting, disconnected, network-changed, paste, open, and input messages float at the top edge of the grid and never resize it. **Edit Host**, **Disconnect**, and **Reconnect** are in the **…** menu.

### Hardware keyboard

While typing in the terminal (not the chat bar), hold ⌘ to see ⌘C and ⌘K in the shortcut overlay.

| Keys | What happens |
|---|---|
| ⌘C | Copies the highlighted selection with the same **Copied N characters** note; with nothing highlighted it does nothing and sends nothing |
| ⌘K | Clears like Ghostty. Local history is deleted. At a shell prompt reported with OSC 133 the screen clears and Ctrl-L redraws the prompt; elsewhere the rows above the cursor are removed and nothing is sent. Does nothing on the alternate screen |
| ⌘. | Esc (iOS maps it for every app, so it is not in the overlay) |
| ⌘V | Paste, with the same confirmation as **Paste** |
| Option | Meta: Option with a key sends Alt with it, as Ghostty does with `macos-option-as-alt = true` (Option-B and Option-F move by word). Option-Shift works with letters only. Option does not type the characters a Mac layout puts on it (∫, é, or @ on some layouts) |
| Shift-Return | Shift+Enter (`ESC [ 27 ; 2 ; 13 ~`, or `ESC [ 13 ; 2 u` with the Kitty keyboard protocol); pi reads it as a new line |
| Option-Return | Alt+Enter (`ESC` then Return, or `ESC [ 13 ; 3 u` with Kitty); pi reads it as a queued follow-up |

Other keys, including other ⌘ shortcuts, are sent as before.

## Filling a password

At a password prompt (the one that turns on **Secure Input**), the keyboard bar and the chat bar's key strip show **Fill Password** when this host has a password to fill. It types the saved password so you do not retype a long `sudo` password on a phone.

- **Which password:** a host that signs in with a password and has **Save Password** on fills that sign-in password. A host that signs in with **This Device's Key** fills its optional **Sudo Password** from the host form. A host with neither never shows the key.
- **Every tap asks** for Face ID, Touch ID, or the passcode, and names the host (**Fill the password for duh@mac-studio**). It never reuses the [5-minute approval](#approval-reuse). Cancelling or failing the check sends nothing.
- **What is sent:** the bytes are typed as a keyboard would (not a bracketed paste), and **Return is not pressed**, so you decide when to answer. A **Filled password** note confirms it, and Oppi keeps nothing after sending.
- **When it is offered:** only while the prompt is on the live screen. Scrolling into history hides it, and so does the prompt ending or the connection closing. Right before sending, Oppi rechecks the live screen: if the prompt ended, its line changed, or the cursor left it while Face ID was up, nothing is sent and a note says so. Output elsewhere (another Herdr pane redrawing) does not stop a fill.
- **Where it goes:** to whatever program on this terminal shows that prompt, not necessarily the host's own `sudo`. In a Herdr pane that ran `ssh` to another machine, the prompt is that machine's, and Fill Password would type this host's saved password into it. Read the host name in the confirmation before approving.
- **VoiceOver:** the key reads **Fill password for** `user@host`.

## Links, paths, and the shell's folder

The terminal reads the shell's folder from OSC 7 `file://host/path`. Only a `file:` URL is accepted. The host in the URL must match the first host the connection reported; a report from a different machine (a nested `ssh`, `tmux` on another host) leaves the folder unknown rather than resolving this server's paths against someone else's. When known, the **…** menu's header shows it.

**Inside Herdr.** Herdr does not pass its panes' OSC 7 through, so a terminal that Oppi started in Herdr would have no folder. There, while Herdr's screen is up, the folder is the focused pane of the host's own Herdr ([Herdr](#herdr)): the pane's foreground folder, or its own folder when Herdr gives no foreground one. It follows focus changes within a few seconds (the Herdr poll), and Browse Files Here, a relative path's **Open**, and the menu header all use it.

- **Only a launch by Oppi counts.** The host's Run on Connect command must be `herdr` or a path to it, with no arguments (both a plain connection and **Open Terminal here** run it). A `herdr` typed into a shell, tmux, vim, and a command with arguments (`--session`, `session attach`, `--remote`) keep the shell's OSC 7 folder: those may be another session or machine, which the default session's snapshot does not describe. While Herdr's screen is not up (the alternate screen), OSC 7 applies as usual.
- **In front, OSC 7 is not used.** Any report made before or inside Herdr is stale or not the focused pane's. The one exception is the host rule: when the latest report names another machine (a pane that ran `ssh`), the folder is unknown, never the host's Herdr's folder, until a report from the first host arrives.
- **Unknown until Herdr answers.** Before the first good snapshot of a connection the folder is unknown. After a good one, a failed read keeps the last folder for up to 25 seconds from that read; then it is unknown. When the poll stops (you leave the terminal screen, it reconnects, or it disconnects) the folder is cleared, and the next poll sets it again.
- **Local only.** A saved machine's panes (`--machine`) are other hosts and never set the folder.
- **Limits.** Herdr's focused pane is server-wide: another client attached to the same Herdr (a desktop, another phone) can move it, and the folder then follows that client's focus. If your Herdr window's sidebar shows a saved machine, the folder is still the host's own focused pane, not the one on screen ([Herdr](#herdr)).

The folder follows the same path rules as any other: it must be absolute, and Browse Files Here and **Open** still need it inside the paired server's home.

A touch-and-hold menu depends on the cell: on an OSC 8 hyperlink, a URL, or a path it offers **Open** beside **Copy** and **Paste**, and a hyperlink also offers **Copy Link**. A word with something to copy but nothing to open offers **Copy** and **Paste**, and a blank cell offers **Paste** alone. **Copy** takes the text you see, and **Copy Link** takes the address an OSC 8 link carries, which the text may not show. Words follow the same rules as a double tap. A trailing `:line` or `:line:column` is dropped for **Open** and kept for **Copy**; a URL is read whole.

- **Open on an `http` or `https` URL** opens the browser chosen in **Settings → General → Open Links** (the in-app browser by default), and the item names the site. Other schemes (`mailto:`, `vscode:`, `ftp:`) can only be copied. An OSC 8 link wins over the text it covers.
- **Open on a path** opens the file in Oppi's viewer when the SSH host is also a paired Oppi server: the two must name the same machine, a tailnet name and its short name included. Two paired servers that could both be that machine match neither, so the terminal does not guess. A relative path resolves against the shell's folder, and with no folder reported can only be copied. A folder opens the Files browser there.
- Owner-host files are rooted at the user's home on the server, so a path outside it offers only **Copy**. A host that is not a paired server offers **Copy** for paths, never **Open**.

**Browse Files Here** in the **…** menu opens the Files browser at the shell's folder when the shell reported one and the host is a paired server. Files are read through that server, not over SSH. Each Open and Browse replaces the one before it. In a terminal Oppi started in Herdr the folder is the focused pane's, so the button appears once Herdr's first snapshot arrives and moves with focus ([Links, paths, and the shell's folder](#links-paths-and-the-shells-folder)).

## Herdr

When `herdr` is on the host, the terminal checks Herdr's API (`herdr api snapshot`) every few seconds over the same connection, in a separate command channel. A button beside **…** at the bottom right, drawn with Herdr's own ram-head mark, turns orange while agents wait at an approval or question. It lists workspaces and agents, each with the status symbol and label of the program-status glyph: Working (animated), Question, Done, or Idle. Each machine's focused workspace and agent are bold. An unrecognized state shows as Unknown.

**The shell's folder.** Herdr's snapshot names each pane's folder (`foreground_cwd`, else `cwd`) and the focused pane (`focused_pane_id`). In a terminal Oppi started in Herdr, Local's focused pane is the shell's folder, because Herdr does not pass its panes' OSC 7 through; [Links, paths, and the shell's folder](#links-paths-and-the-shells-folder) has the rules, the 25-second grace after a failed read, and the limits (the focused pane is server-wide, and it is the host's own, whatever machine the sidebar shows). A Herdr that omits these fields leaves the folder unknown. Saved machines never set it.

**Saved machines.** Machines saved in the host's Herdr (`herdr machine add`, listed by `herdr machine list`) show in the same sheet under their Herdr label, after **Local** (the host's own Herdr). The host's Herdr reads each one with `herdr --machine <profile-id> api snapshot` over its own saved SSH connection, so the phone needs no access to those machines. Each machine heading says what is wrong when it cannot be read (the SSH or Herdr error, or a timeout after 10 seconds without an answer), **Disabled in Herdr** for a disabled profile, which is not read, or how many agents there wait on you. Machines are read at the same time and each shows as soon as it answers, so one that is down does not hold up the others. A machine that stops answering keeps showing what it last reported under its error, and its agents leave the orange count, which adds up waiting agents on every machine that answers. With no saved machines the sheet shows Local alone, without headings. A Herdr too old to list machines shows Local alone.

Herdr decides the state from the agent's screen or its integration and does not pass OSC 7501 through. A Herdr version that lists a pane's OSC 7501 records (`program_status`) is read like a plain terminal's records, including the blocked kind (Needs approval, Sign-in, Question). Without records, Herdr cannot say what kind of wait it is, so a blocked agent reads as Question, and a question Herdr does not recognize reads as Done. Oppi's `ask` extension tells Herdr's Pi integration when it waits, so a pi question reads as Question. Tapping a row runs `herdr workspace focus` or `herdr agent focus` on the machine that row belongs to (with `--machine` for a saved machine). A Herdr window that shows that machine follows; Herdr has no command to switch which machine a window shows, so if yours shows another machine, pick that one in Herdr's sidebar. Hosts without `herdr` are checked once per connection and then left alone.

## Rex

When the host runs [Rex](https://www.superlogical.com/rex/docs/), the terminal follows its sessions over the same connection, in a separate command channel, and the list updates as Rex changes (Herdr's is read every few seconds). A **Rex Sessions** button beside **…** at the bottom right, drawn with a dinosaur glyph after Rex's app icon (Oppi's own drawing, not Superlogical's), opens the list and turns orange while a pane waits at an approval, question, or sign-in. Each session lists its panes in window order, named by the program that reported its status (such as `pi`), else the terminal's title, with that title and, for a session with more than one window, the window's name underneath. The pane Rex types into (the focused pane of the session's active window) is bold.

Rex passes each pane's [OSC 7501](#program-status-osc-7501) reports through, so a pane's status is its program's own, rolled up the way this terminal rolls up its records, including the blocked kind (Needs approval, Sign-in, Question). A pane whose program never reported shows no status.

- **How it reads:** one long-lived command on the host (`nc -U` to Rex's own socket, the same bridge a [Rex pane](#opening-a-rex-pane) uses) carries Rex's control protocol, so the phone needs no route to Rex itself, and Rex's own Tailscale serving can stay off. The first read takes every session, its view, and each terminal's title, folder, and status once; after that Rex's events change the list in place: titles, folders, and status reports, blocks and sessions coming and going, and layout changes (which read the session's view again, at most one read at a time per session). A burst of changes reaches the list as one update, at most one per ~150 ms. Rex replays no events, so after a dropped stream the list is read in full again on a new one, after 1 s, doubling to 30 s; opening the sheet reads it once more too.
- **When Rex cannot be read,** the command's exit status says why, from the same one exec: **Rex is not running on this host** (installed, no server listening; it never starts one) is asked again after 15 s, doubling to 60 s. A host with no `nc` that supports Unix sockets (Debian's `netcat-traditional` and BusyBox's do not), or with no `rex` (the CLI inside the Rex app on macOS, else on the `PATH`), is asked once per connection: the Rex Sessions button is not offered in a terminal, and a [Rex host's](#a-rex-host) screen says what is missing.
- **If Rex stops answering,** the list keeps what it last reported under the reason (the connection closed, or Rex is not running), and its panes leave the orange count. Session rows do nothing when tapped.

### A Rex host

With **Multiplexer** set to **Rex** in the host's form, tapping the host (or **Connect** in its form) opens its Rex sessions as a screen of their own instead of a terminal: the same rows as the **Rex Sessions** list, kept current by one Rex stream while the screen shows, so it changes as Rex does. Pull down to read Rex once more, to connect again after a failure, or to try again after fixing the host. Tap a pane to open it ([Opening a Rex pane](#opening-a-rex-pane)); **Back** returns to the sessions. **Shell** (top right) opens the host's login shell, the one already open if it still is. No shell is opened until you ask.

- **How it connects:** the screen signs in a connection of its own with the host's sign-in, asking for a password, Face ID, or host trust over the screen as the host list does. It runs no shell or PTY; it opens the one Rex stream beside, as a terminal does. It closes when you leave the screen or Oppi goes to the background, and signs in again when the screen shows again; a connection that drops while the screen shows signs in again by itself.
- **When Rex cannot be read,** the screen says which of three things is missing, and what to do: **no usable `nc`** on the host (install a netcat that supports Unix sockets, `nc -U`, such as `netcat-openbsd`), **Rex not installed**, or **Rex not running** (start it with `rex server start`; the list fills in by itself, asked again after 15 s, doubling to 60 s). For the first two, pull down to try again once it is fixed.
- **Open Terminal here** on a Rex host opens a login shell in the folder, as for a host without a multiplexer.

### Rex sessions on the Terminal tab

When a saved host has **Multiplexer** set to **Rex**, or Oppi has seen Rex on it, the Terminal tab leads with a **Rex** section for it, above the host list: the host's name, then one row per Rex session with its name, its pane count, and how many panes wait on you (`3 panes · 1 needs you`), and the status that leads the session on the right (a blocked pane wins over a working one). With no such host there is no section. Each Rex host has its own heading and rows.

- **Which hosts:** a host counts when it is saved with Multiplexer: Rex, or when Oppi has seen Rex on it: a terminal connected to the host read Rex (the bar's **Rex Sessions** list was able to load, whatever the host's Run on Connect command), or a [Rex pane](#opening-a-rex-pane) opened on it. That is remembered on this device for the host as saved (the same user, address, and port; an edited address starts over) and goes with the host when it is deleted; it holds no secret. The tab dials only these hosts: a host Oppi has never seen Rex on is not contacted from the tab. If a read finds **Rex not installed** on a host that is there only because Rex was seen on it, Oppi forgets it and the section goes; **Rex not running** keeps the host and the section says so. A host saved with Multiplexer: Rex always keeps its section and says what is missing. Its normal row below is unchanged: a host that was not saved with Rex still opens its own terminal.

- **Live:** while the tab is showing, Oppi follows each Rex host the way the host's own [sessions screen](#a-rex-host) does: a connection of its own that runs no shell, and one Rex stream whose events update the rows as Rex changes. The stream stops when something covers the tab (a terminal, a form) or Oppi goes to the background, and reads Rex again on return. Nothing polls. Pull down to read Rex again, or to try again on a host that had no `nc` or no Rex.
- **Tap a session** to open it as a [Rex terminal](#opening-a-rex-pane) on the pane Rex types into there (else its first pane). A session that already has a terminal open shows that terminal and moves it to that pane, instead of opening a second connection.
- **It never asks on its own.** A host that would need a password, a trust decision, or Face ID to sign in (its key is not trusted yet, its password is not saved or not approved in the last 5 minutes, or its device key is not approved) shows **Tap to connect** instead; the tap signs in over the usual password, trust, and Face ID prompts, and the rows follow. After the first tap, an approval still inside its [5 minutes](#approval-reuse) lets the tab sign in by itself on the next visit. A sign-in the tab started that runs into a changed or untrusted host key, or a missing password, shows nothing over the tab: the heading says what it hit, beside **Tap to connect**, and the tap shows the trust decision or the password sheet. A failed sign-in says why under the heading, beside **Tap to connect** to try again. Leaving the tab for another screen closes these connections, and they sign in again on return; a terminal or form opened over the tab leaves them up. When Rex cannot be read, the section says which of the [three things](#a-rex-host) is missing.
- **The host's row** below stays as it is: a Rex host's still opens its Rex sessions screen.
- **VoiceOver:** each session is one button named `session, N panes, M need you` whose value is its status; tapping it and activating it do the same thing.

### Opening a Rex pane

Tapping a pane opens its **session** on this device, full screen, as a terminal of its own beside the host's shell: the same grid, keyboard, chat bar, program shortcuts, status, and files as any terminal here. It shows what the pane shows now, with its history, then keeps up with it live. The terminal stands for the whole Rex session, so you move between the session's panes without leaving the screen, and tapping any pane row of a session that is already open shows that terminal and moves it to the tapped pane, instead of opening a second one. The switcher lists one entry per session, **Rex · *name***, named for the pane it shows, and the **Rex Sessions** button is there too, to open another session.

- **Pane switcher:** with more than one pane in the session, the bar's trailing pill has a button beside **Rex Sessions** that draws the pane on screen's icon: a tile with the first character of the pane's title for a pane whose program reports [status](#program-status-osc-7501), because programs put their own mark first in it (`π` for `π - oppi`, `✳` for Claude Code's `✳ …`); a lowercase Latin initial is uppercased, other characters are kept. Without a title it uses the `app` the status names (`P` for `pi`), then Rex's label. A plain shell has the terminal glyph. Oppi names no program for this: the rule is the same for every pane. Tap it for a menu of the session's panes, with a check on the one on screen and, when the session has more than one window, a section per window; choose one to show it. **New Pane** ends the menu ([New pane](#new-pane)). The order is Rex's: the session's windows in order, and inside a window the panes in layout order (left to right, top to bottom through the splits). VoiceOver reads the button as **Pane** with the value "name, 2 of 3". A session of one pane has no switcher. Whenever the pane changes, by a swipe, the menu, a minimap cell, or an action, the icon rolls to the next one: up when the pane is further along the strip, down when it is before (a crossfade with Reduce Motion).
- **Swipe:** swipe sideways on the grid and the screen follows your finger, the next or previous pane's name waiting on the side it comes from. Let go past about 56 pt, or after a short flick, and the screen slides on to that pane with a light tick (when Haptics is on in Settings); the incoming pane's name covers the grid until Rex's snapshot of that pane is on it (at most about 2 s, then whatever the grid shows), so the old pane's screen never slides in as the new one. Let go short and it springs back with no tick. Past the first pane the screen resists and springs back; past the last one it opens a [new pane](#new-pane). The screen's left edge stays Back, and scrolling the history up and down and selecting text work as before. With VoiceOver, the grid's actions **Next Pane** and **Previous Pane** do the same, without a drag (the screen slides by itself). The menu and the minimap's cells slide it the same way.
- **New pane:** swipe left past the last pane and the screen follows your finger as it does for a switch, with a **New Pane** card (a plus) arriving on the right: dimmed until you are about 56 pt along (or let go with a short flick), then lit with a light tick (when Haptics is on in Settings, once per crossing, with none again on letting go). Let go past that and the card slides in and stays ("New Pane…") while Rex makes the pane: one shell in a new split after the pane on screen, side by side with it, in that pane's folder when the shell has reported one (otherwise Rex's default, your home folder). Oppi then shows it like any other switch: the card takes the pane's name until its screen is there, the switcher counts it and its icon rolls to it, and the minimap shows as for any switch. Letting go short, or against the first pane (a swipe right), springs back and asks Rex for nothing. A session of one pane offers it too, so one pane can grow; the switcher appears with the second pane. VoiceOver's grid action **New Pane** and the last item of the switcher's menu do the same without a drag. As with Rex's own new split, it ends any zoom in that window on the host. Like switching, it never moves focus on the host: the new pane is only what this screen shows, though it stays in the session for Rex's other clients. If Rex refuses (the pane closed meanwhile, the session is full) or does not answer, the card slides away to the pane you were on, a notice says why, and you can try again; one pane is opened at a time, and with Reduce Motion the card crossfades like any switch.
- **Minimap:** a small map of the pane's window that shows only while you switch panes, at the grid's top right: one rounded cell per pane at its place in the window, the pane on screen in the accent color, the others gray. It is hidden at rest, when a terminal opens, and while you scroll history. It fades in (about 0.15 s) when a sideways swipe begins, stays while your finger is down, and shows the accent moving to the new cell when the pane changes (no animation with Reduce Motion); about 0.8 s after the screen settles on the pane, or springs back, it fades out. A switch from the bar's menu, a cell, or VoiceOver's Next and Previous Pane shows it the same way, and a new swipe during the fade-out keeps it. Tap a cell to show that pane, while the map is showing; hidden, it takes no touches and VoiceOver does not read it (the bar's switcher and the grid's actions do the work). With Reduce Motion the map appears and goes without fading, on the same timing. A window of one pane has no minimap; a swipe from one into a window of several shows the map as the new window arrives, and the other way it fades out. The map draws the window's tiled layout; a floating pane is in the switcher's menu but has no cell.
- **Names:** a pane is named by its title (the program's, or the shell's), else Rex's label for it, and the switcher follows Rex: panes opening and closing, layout changes, and new titles reach it as Rex sends them. Unlike the sessions list, a name does not use the program that reported its status.
- **Display only:** showing another pane takes it for size (below) and opens its stream; it never moves focus on the host. The pane Rex types into there, and the window it shows, stay where they were.
- **If the pane on screen closes** in Rex, the terminal moves to its neighbour (the next pane, else the one before). When none is left it ends and says the pane closed. Rex closes a pane whose program exited, so a shell that exits moves you on the same way; if it was the last pane, the terminal ends and shows the program's exit status. A pane Rex keeps open after its program exited stays on screen until you leave it.
- **How it connects:** a new connection to the same saved host, with the same sign-in, runs no shell. One connection serves the whole session: its main channel is a bridge to Rex's own socket on the host (`nc -U`, at `~/Library/Application Support/rex/server.sock` on macOS, `$XDG_RUNTIME_DIR/rex` or `~/.local/state/rex/run` elsewhere), and Oppi speaks Rex's client protocol over it, as Rex's own apps do, attached to the session. The pane on screen has a data connection on a second channel: Rex starts it with a snapshot of the pane's screen and history, then sends the program's output as it comes. The screen draws as soon as its part of the snapshot arrives; older history and images fill in behind it while you read, so a pane with a long history opens about as fast as one without. Oppi asks Rex to compress both connections, so a long history costs about a fifth of its size in data. Showing another pane closes that stream and opens the new pane's, whose snapshot replaces the grid; quick swipes are taken one at a time and end on the last pane asked for. Rex trusts a caller on its socket as the account it runs as, so it needs no sign-in or network access of its own; its Tailscale serving can stay off. A host without `nc`, or whose Rex is not running, says so instead of opening.
- **Size:** while a pane is on screen here, it takes this screen's size, as the Rex client that owns it. A Rex window on the Mac showing the same pane reflows to that size until you move to another pane here, close the terminal, or Oppi leaves it; Rex then hands the pane back to the next client in line, such as the Mac app.
- **Typing:** keys, pastes, and the chat bar go to the pane on screen through Rex, in order. Rex's terminal on the host answers the program's own queries, so this one does not answer them a second time.
- **It keeps running:** Disconnect, Back, or Oppi going to the background closes this device's view, never the panes. Reconnecting, or returning to a terminal that was on screen, shows the pane that was on screen again from Rex's snapshot, history included. Program status (the glyph beside the bottom bar) is the pane on screen's own: it starts empty after a switch and fills as that pane's program reports.
- **Limits:** Rex sends no theme Oppi applies; the host's Ghostty theme still colors the grid. Legacy X10 mouse reports past column 95 are not UTF-8 and arrive mangled; programs that use SGR mouse reports (the usual default) are unaffected.

## Clipboard

When a program on the host copies text with OSC 52, the text goes on this device's clipboard and a **Copied N characters** note appears. Herdr forwards a pane's copy this way (copy-on-select, an agent's `/copy`), as does tmux with `set-clipboard on`. Only UTF-8 text up to 1 MB sent to the standard clipboard (`c`) is copied. Requests to clear it and writes to the X11 selection or primary buffer are ignored. Copying is write-only: the host never reads this device's clipboard, and clipboard queries get no reply. A remote copy applies only while that terminal is on screen and Oppi is in front. Your own double-tap or selection copy is allowed regardless. Paste is always your action, through **Paste** or ⌘V.

## Program status (OSC 7501)

The terminal answers the Program Status Protocol support query (`ESC ] 7501 ; ? ST`) with the revision 0.4 reply (`?:states=idle,working,done,blocked,error:kinds=permission,question,auth`), so programs that detect support first, such as Pi 1.1.0, start reporting. This is the only OSC reply the terminal sends. Reports (idle, working, done, blocked, error, with an optional app, title, and message) follow the [specification](https://www.superlogical.com/rex/docs/build/program-status): one record per id, `clear` removes a record and its children, at most 256 records. `working` and `blocked` records drop when the shell shows its next prompt (OSC 133 A) or the shell or connection ends, while `done` and `error` stay. Reset (RIS) clears everything.

While a program has reported, the bottom-right button shows a status symbol: a blue progress mark while working, an orange hand, question, or lock while blocked, and a grey dot at rest. Tap it for the list of programs, with this host named at the top. Done and Error settle to the grey rest state (a stop symbol once the connection has ended); when the root program finishes after working or waiting and nothing else is running, the button shows green or red for a moment first. A blocked record wins over a working root, as in a thread. Nothing shows until a program reports.

When any record is blocked, a card floats over the top of the terminal naming the kind, the saved host, and the program's message. It does not resize the terminal and is not a dialog: you answer in the terminal or chat bar. If it covers the program's prompt, tap it or swipe it up (VoiceOver: **Dismiss**); it folds into the status symbol, which stays orange and lists the message. It stays away while the program repeats the same report and returns for a different kind of wait, the next time the program blocks, or a new message after the program's reports pause for a second.

## Progress (OSC 9;4)

A program can report progress with OSC 9;4 (`ESC ] 9 ; 4 ; state ; percent ST`; cargo, `brew`, `winget`, and `systemd` tools send it). The status glyph draws it as a ring:

| Report | Ring |
|---|---|
| `1;N` set | Blue, filled clockwise from the top to N% |
| `3` indeterminate | Blue, a short arc that spins |
| `2` or `2;N` error | Red, filled to N%; with no number, a full still ring (the work stopped) |
| `4` or `4;N` pause | Orange and dashed, filled to N%; with no number, a full ring |
| `0` remove | No ring |

With an OSC 7501 report too, its symbol stays in the middle and the ring goes around it. Progress alone is the whole glyph and not a button. VoiceOver reads **Progress 40%** (also **Progress paused at 60%**, **Progress failed**, **Progress, in progress**) after the status. With **Reduce Motion** on, an indeterminate report is a dotted full ring. Each report replaces the previous one, and one not renewed for 15 seconds goes away, as in Ghostty. A reset (RIS) or the end of the connection clears it. Progress shows no card and no haptic.

## Notifications and the bell

A program can notify the terminal with OSC 9 (`ESC ] 9 ; text ST`, iTerm2) or OSC 777 (`ESC ] 777 ; notify ; title ; body ST`, rxvt and Ghostty). The same card shows it, headed **Notification**, and leaves after six seconds or when you tap it. Notifications less than a second apart become one that updates its text. A blocked program's card comes first, and a notification waits behind it. A new card gives a warning haptic, at most once a second. A bell (BEL) gives a light haptic and no card, and bells within one second count once. The terminal hears these while its connection is open, including after you leave its screen ([Keeping a terminal open](#keeping-a-terminal-open)). Programs inside Herdr usually notify Herdr, and Herdr's own notifications use Kitty's OSC 99, which is not read yet.

## Credentials and host trust

- **Metadata:** host, port, username, sign-in choice, and Run on Connect are stored in app preferences. Passwords never are, and are never logged. Each host has its own id, and changing its hostname, port, username, or sign-in method removes its saved password and sudo password without touching another host's.
- **Unsaved password:** used for one connection attempt; Reconnect asks again.
- **Saved and sudo passwords** live in the app's private, this-device-only Keychain, never synced or migrated, behind Face ID, Touch ID, or the passcode (a device passcode is required to save one). Each is bound to its host's id, so copying one host's secret onto another host's item does not sign in. The form never shows a saved sudo password: type a new one to replace it, or tap **Remove Saved Sudo Password**. Reading at connect needs approval that Oppi [reuses for 5 minutes](#approval-reuse).
- **Device key:** on a physical device the per-device P-256 SSH key lives in the Secure Enclave, and signing needs user presence (reused 5 minutes). The simulator uses a labelled software key, which is not evidence of hardware protection. Password sign-in creates no key.
- **Trusted host keys** are stored in the same Keychain, shared by Terminal and **Set Up a Computer**. A changed host key blocks sign-in. **Forget Trusted Key** asks for confirmation; verify independently why the key changed before trusting its replacement.
- **Delete Host** deletes that host and its saved passwords, not the device key or trusted host keys, which stay keyed by host and port. If the host list cannot be read, saving is blocked until **Reset Host List** removes it; add hosts again afterward. Reset does not search the Keychain.

## Keeping a terminal open

While Oppi is in the foreground, a connected terminal stays connected when you leave its screen (Back, another tab, another session). Tap that host in the list (it reads **Connected**) to return to the same live channel and grid, with no reconnect or sign-in. Oppi keeps one terminal per saved host and folder, and connecting an identity that already has one shows it; **Reconnect** and a connect after the shell ended open a new one.

A terminal ends when you tap **Disconnect**, when the remote shell or command exits or the connection drops, when you save changes to the host or delete it, or when the background grace ends. Saving the host unchanged keeps it, and so does saving or removing only a password. While off screen, Oppi still reads its output, answers its terminal queries, and checks the connection after a network change. The Herdr list and program shortcuts load again when you return.

### Switching terminals

With more than one terminal open, a **Switch terminal** button (stacked rectangles) sits beside **…**. Its menu lists every open terminal, each as `user@host` over the folder's last component, or over the Run on Connect command or **Login shell** for a host's own terminal. A green dot marks a connected terminal. A terminal whose program is blocked shows that status symbol and what it waits on. The terminal on screen is checked, and the order is hosts by name, a host's own terminal first, then its folders.

Choosing one swaps to that terminal's live channel with no dialing or sign-in, and the one you left stays open and keeps reading. **Reconnect** and **Edit Host** then act on the terminal now shown, from whichever screen opened this one: a Reconnect that needs a password asks for that terminal's host, names it in the sheet, and **Save Password** edits that host. Chat-bar text and attachments stay with their terminal until you leave the terminal screen. The button is hidden with one terminal open, and VoiceOver reads **Switch terminal** with the count.

## Approval reuse

Face ID, Touch ID, or the passcode is asked when a sign-in needs your device key or a saved password. Oppi remembers that approval for 5 minutes, separately for the device key and for each host's saved password, so a reconnect in that window does not ask again. Oppi keeps its own approval and does not widen the system's biometric reuse. It ends early when the 5 minutes pass, when App Lock locks or covers Oppi, and on any sign-in or approval failure. Approvals are never saved to disk, and a connected terminal does not depend on them.

## Network and reconnect

When Oppi's in-app Tailscale node runs, tailnet names (`*.ts.net` or `*.beta.tailscale.net`, with or without a trailing dot) use it. Other hosts, and tailnet names while the node is stopped, use direct TCP through your current network, including a system Tailscale VPN.

Oppi checks SSH liveness every 60 seconds by opening and closing an empty session channel (15-second reply timeout, no shell, command, or PTY), and direct TCP also uses kernel keepalives. Failure closes the connection and shows **Disconnected** with **Reconnect**. After a Wi-Fi or cellular change, one SSH round trip decides: a live shell carries on, a dead one shows **Disconnected**.

Going to the background keeps the shell running and reading output for about 25 seconds under an iOS background task. Return within that time and nothing reconnects. A connect still signing in or dialing when Oppi backgrounds is cancelled, and one that finishes there is closed again. Otherwise Oppi closes the connection before iOS can suspend it (**Oppi went to the background.**), because a suspended app would silently lose the bytes the host sends. On return, a terminal that was on screen reconnects on its own and signs in like **Reconnect** ([Approval reuse](#approval-reuse)), after you unlock if App Lock is on. A terminal you had left is not reconnected. If that sign-in fails or is cancelled, it shows **Disconnected** with **Reconnect**. These notices float over the grid and do not resize it. Reconnect always opens a fresh shell and does not replay input, so use `tmux` on the host if work must survive a disconnect. A [Rex terminal](#opening-a-rex-pane) is the exception: its panes kept running in Rex, and reconnecting shows the pane you were on as it is now. The Rex list has nothing to resume either: it follows Rex over the closed connection's stream, so coming back reads Rex in full again.

## Limits

- Hosts are saved on this device only. There is no private-key import, keyboard-interactive sign-in, or forwarding.
- Images use the direct medium only, and Unicode-placeholder (tmux) images do not draw ([Images](#images)).
- The SSH library supports Ed25519 and ECDSA host and user keys, Curve25519 and ECDH key exchange, and AES-GCM. RSA-only and legacy-only servers fail with an unsupported-algorithm error, and a server offering only keyboard-interactive cannot accept password sign-in here.
- Connection, authentication, and terminal-opening waits are bounded, and a rejected credential, changed host key, unreachable host, or unsupported algorithm shows a visible error.
- Secure Enclave and biometric approval need physical-device testing.
