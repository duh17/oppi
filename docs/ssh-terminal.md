# SSH Terminal experiment

SSH Terminal opens an interactive shell on a host saved on this iPhone or iPad. It is an opt-in experiment, off by default. It does not run through the Oppi server and does not change Pi session ownership.

## Set up a host

1. Turn on **Settings → Experiments → SSH Terminal**.
2. Open **Settings → SSH Hosts**. That opens the host list. Opening the list does not dial and does not read the Keychain, so it does not ask for Face ID.
3. Tap **Add**. Enter a host, port (default 22), and username. The host has no default. Enable Remote Login or `sshd` on that host. **Edit** opens the same form for a saved host.
4. Choose **Password** or **This Device’s Key**.
   - **Password:** enter the password at connect. **Save Password** is optional.
   - **This Device’s Key:** copy the public key and add it as one line to `~/.ssh/authorized_keys` on the host. Oppi does not install it for you.
5. Tap **Connect**. Compare the displayed host-key fingerprint with the host’s fingerprint through an independent, trusted channel. Trust it only after they match. Oppi sends no credentials before host-key validation succeeds. You can also tap **Save Host** and connect later from the list.

For example, on a Mac with an Ed25519 host key:

```sh
ssh-keygen -lf /etc/ssh/ssh_host_ed25519_key.pub
```

After you save a host, **Terminal** appears directly below **MCP Servers** in the workspace sidebar. Tap it to open the same list. Tap a row to connect and open the shell. The password sheet and host-key prompt appear on the list or the form, whichever you tapped Connect from. A row shows `user@host`, the port when it is not 22, and the Run on Connect command, or **Login shell**. Two rows can use the same machine with different Run on Connect commands. Swipe **Delete Host** removes that saved host and its password only. **Edit Host** in the live terminal opens the form for the connected host. Turning the experiment off hides both entry points and does not create a key. **Tailscale → Check a Machine for Oppi** remains available independently.

## Font and icons

The terminal uses **Settings → Text → Code Font** and **Code Text Size**, like code blocks and tool output. At 100% it is 13 pt. Changing either redraws an open terminal and resizes the remote shell to the new cell size.

Prompt icons from starship, powerlevel10k, oh-my-posh, and similar (Powerline separators, git, folder, and language icons) come from the bundled Nerd Fonts Symbols font, which works with every code font.

## Run on Connect

**Run on Connect** runs one command in the terminal instead of a login shell. This is the same exec-with-TTY request as `ssh -t host 'command'` or OpenSSH `RemoteCommand` with `RequestTTY yes`. Enter `herdr` to attach your Herdr session, or `tmux new -A -s main` for tmux. The connection ends when the command exits and the status names the command; **Reconnect** runs it again. The command must be on the `PATH` that non-interactive SSH commands see. Leave it empty for a normal login shell.

## Input bar, touch, and keyboard

The terminal picks its input from what the host tells it; it does not inspect the host's processes. A program that reports [OSC 7501](#program-status-osc-7501) on the root record as a coding agent gets the chat input bar. The agent ids are `pi`, `claude`, `codex`, `opencode`, `gemini`, `amp`, `aider`, `goose`, `crush`, `droid`, `cursor-agent`, `qwen`, `kimi`, `copilot`, `kilo`, and `grok`, also with a suffix such as `claude-code`. When **Run on Connect** starts `herdr`, the terminal is a Herdr client for the whole connection and gets the chat bar while Herdr's focused pane runs an agent. Anything else, such as a shell, `vim`, `tmux`, a program that does not report, a cleared root, or a report sent before the shell's latest prompt (OSC 133), gets direct terminal typing: the bar is hidden and a tap opens the keyboard with the Esc/Tab/Ctrl/arrow bar. Coding agents that do not report OSC 7501 yet (OpenCode, Copilot CLI, Gemini CLI, and others) start in direct typing; switch to the chat bar by hand. Herdr started by typing `herdr` in a login shell is not detected either. To switch by hand, use **Use Chat Bar** or **Type in Terminal** in the … menu, or the chat button on the terminal keyboard's bar; that choice wins until the detected program changes.

The chat input bar is Oppi's chat composer. Type or dictate (same dictation as chat), edit, then **Send**: Oppi pastes the text as one block (bracketed paste when the app supports it) and presses Enter. Send with an empty bar presses Enter alone. Autocorrect, capitals, and smart punctuation are off. While the bar is focused, a key strip offers the program's keys (such as Thinking and Model), then the arrows, then Esc, Tab, Ctrl-C, and Ctrl-D in one row; swipe it for the keys that do not fit. A keyboard button, pinned at its right end, switches to typing straight into the terminal with the Esc/Tab/Ctrl/arrow bar. That switch stays in direct typing. A tap with the keyboard down opens it, including when the app asked for mouse input. While that keyboard is up and the app asked for mouse input, a tap is a click at the cell and the keyboard stays up; hide it with ⌄ on the keyboard bar. That bar has two rows: Esc, Ctrl, Alt, Tab, and the arrows, then Paste and the program's keys. Swipe either row to reach keys that do not fit; both move together. The chat button and ⌄ stay pinned at the right end, stacked on a tinted dock. Otherwise a tap hides the keyboard. **Use Chat Bar** (in the … menu, or the chat button on the terminal keyboard) returns to the input bar. Starting an agent from the terminal keyboard moves typing to the input bar.

The chat bar grows over the terminal instead of shrinking it. The terminal keeps room for the bar at rest: one line, plus its row of buttons and key strip while that row shows (while the bar is focused, or while it holds an attachment). A longer draft, attachments, file pills, suggestions, and the dictation or send-failure note cover the bottom rows instead, so the remote terminal is not resized while you compose and the program does not redraw. When the bar covers the row the program's cursor is on, the terminal's picture moves up by the fewest whole rows that keep that row above the bar, and moves back when the bar shrinks; the top rows slide under the top edge meanwhile. While you read history, or while a finger is on the terminal or a flick coasts, the picture holds still; it eases into place once you are back to live. The remote terminal is resized when the keyboard comes up or goes down, on rotation, and when the chat bar appears or goes away.

### Program shortcuts

The key strip and the terminal keyboard's bar add buttons for the agent that reports itself (or the shell when none does), named by what they do. Each button sends the key that program has bound right now:

| Program | Buttons (default key) | User file read |
|---|---|---|
| Shell | History (^R), Clear (^L) | none |
| pi | Thinking (⇧Tab), Model (^L), Tools (^O); Stop when interrupt is not Esc | `${PI_CODING_AGENT_DIR:-~/.pi/agent}/keybindings.json` |
| Claude Code | Mode (⇧Tab), Model (⌥P), Transcript (^O), Todos (^T), Background (^B) | `${CLAUDE_CONFIG_DIR:-~/.claude}/keybindings.json`, contexts Global, Chat, Task |
| Codex | Transcript (^T), Effort − (⌥,), Effort + (⌥.); Stop when interrupt is not Esc | `[tui.keymap.*]` in `${CODEX_HOME:-~/.codex}/config.toml` |

The file is read once each time that program changes, through a side command on the same connection, and follows that program's rules: pi and Codex entries replace an action's keys and `[]` removes it; Claude Code entries add keys, and a default key bound to `null` or to another action stops counting. A missing or unreadable file means the defaults. For Codex only the `tui` tables leave the host, and only table headers, dotted keys, and string arrays are read (not inline tables, profiles, or project `.codex/config.toml`). The variables are those of a non-interactive SSH command, which may differ from the agent's own environment. Actions bound to Esc, ^C, Tab, ↑ or ↓ are not repeated, `super`/`cmd` keys are left out, and Claude Code chords are sent as one write. Other agents get the fixed keys only. Under Herdr, the buttons follow the agent in the focused pane.

Photos and files from **+** or a pasted image are saved on the host before Send, in an owner-only `oppi-ssh` folder under `$TMPDIR`, over the same SSH connection. A host that sets no `$TMPDIR` gets `/tmp/oppi-ssh-<your uid>` instead, so the folder is yours alone on a shared `/tmp`. The save is refused, with its reason shown in place of the path, when that folder is a symlink, is not a directory, or belongs to another user, and the folder is always made owner-only (700). The prompt then lists each file's path on its own line, so the agent can read it. Each file is limited to 32 MB.

A password prompt on screen turns on the keyboard's secure entry, and the bar shows **Secure Input** with a lock. Third-party keyboards, dictation, and keyboard learning then do not see what is typed. Oppi recognizes a prompt from the cursor's own line on the live screen, so it works for `sudo`, `su`, `ssh`, and `ssh-agent` in a normal shell and inside a Herdr pane, and typing `echo Password:` at a shell prompt does not turn it on. It stays on while the secret is typed, including the `*` a prompt echoes after each key, and ends when the cursor leaves that line. Reading local history does not end it. If the chat bar is the input at that moment, typing moves to the terminal until the prompt ends, then back; switching by hand meanwhile wins, and hiding the keyboard counts as such a choice. A password is never typed into the chat bar's draft.

- In direct typing, holding ⌫ repeats, on the on-screen keyboard and on a hardware keyboard. After about a second of holding, each repeat deletes a word (Ctrl-W, in the app's keyboard protocol) instead of a character, as in iOS text fields; letting go starts over with characters. Words are deleted only on the normal screen (shells and agent prompts such as pi or Claude Code). A full-screen app on the alternate screen (vim, nano, less, Emacs) keeps getting ⌫, since it may bind Ctrl-W to something else.
- Touch and hold the space bar, then slide, to move the cursor: one ← or → per character cell of travel and one ↑ or ↓ per row, sent once per frame in the app's cursor-key mode. In a shell, ↑ and ↓ walk the command history. The trackpad moves nothing while a keyboard such as Japanese is composing.
- Keys and words the keyboard inserts at once (by sliding across the keys, for example) go to the shell immediately, as one write that leaves an armed **Ctrl** or **Alt** for the next key.
- The keyboard's mic dictates into the shell as you speak. iOS keeps revising its guess, and each revision reaches the shell at once: one backspace per character back to the first one it changed, then the new text. When you tap the mic to stop, iOS's final text replaces the guess the same way. Oppi tracks what the keyboard typed since the last arrow, paste, tap, Return, or hardware key; a revision of text from before one of those is dropped.
- Text the keyboard hands over in one piece, such as a dictated phrase, that contains a newline or a control character asks first, like a multi-line paste, and is then pasted as one block. Return alone is Enter. Writing Tools is off there.
- On the terminal keyboard's bar, **Alt** then Return sends Alt+Enter (the same as Option-Return below). There is no Shift key on the bar, so Shift-Return needs a hardware keyboard.

### Hardware keyboard

While typing in the terminal (not the chat bar), a hardware keyboard adds these. Hold ⌘ to see ⌘C and ⌘K in the shortcut overlay.

| Keys | What happens |
|---|---|
| ⌘C | Copies the highlighted selection, with the same **Copied N characters** note as a touch selection: during a touch-and-hold drag, or while a double-tapped word or a released selection is still highlighted. With nothing highlighted it does nothing and sends nothing. |
| ⌘K | Clears like Ghostty's ⌘K. Local history is deleted. At a shell prompt the shell reported with OSC 133, the screen is cleared and a form feed (Ctrl-L) is sent so the shell redraws its prompt. Elsewhere the rows above the cursor are removed, the cursor's row moves to the top, and nothing is sent. On the alternate screen (vim, less, a TUI) ⌘K does nothing. |
| ⌘. | Esc. iOS turns ⌘. into Esc for every app, so it is not in the overlay. |
| ⌘V | Paste, with the same confirmation as **Paste**. |
| Option | Meta: Option with a key sends Alt with that key, as Ghostty does with `macos-option-as-alt = true`. In a shell Option-B and Option-F move by word. Option with Shift works with letters only; Option-Shift with another key sends nothing, since iOS does not report which shifted character it would be. Option does not type the characters a Mac layout puts on it (∫, é, or @ on some layouts). |
| Shift-Return | Shift+Enter: `ESC [ 27 ; 2 ; 13 ~`, or `ESC [ 13 ; 2 u` when the app turned on the Kitty keyboard protocol. pi reads it as a new line without sending. |
| Option-Return | Alt+Enter: `ESC` then Return, or `ESC [ 13 ; 3 u` with the Kitty keyboard protocol. pi reads it as a queued follow-up message. |

Other keys, including other ⌘ shortcuts, are sent as before.
- With the keyboard hidden, a tap starts typing: into the terminal when that is the input (a shell, or after the keyboard button or **Type in Terminal**), even if the app asked for mouse input; into the input bar for an agent.
- While the direct keyboard is up and an app asks for mouse input (Herdr, tmux with `mouse on`, many TUIs), a tap is a click at the cell and the keyboard stays up. Hide that keyboard with ⌄ on its bar. A tap hides the keyboard only when the app did not ask for mouse input.
- While the chat bar is the input and an app asks for mouse input, that tap is a click at the cell.
- A tap on the grid waits a moment before hiding the keyboard, so a second tap can copy. The ⌄ key hides it at once. Double-tap a word to copy it: the first tap still runs (opens the keyboard, or clicks in a mouse app), and the second tap only copies the word that was under the finger on the first tap. It does not hide the keyboard or send a click. Paths such as `/usr/local/bin/thing` and URLs such as `https://example.com/a/b?x=1` count as one word. A trailing colon is dropped (`src/x.swift:42:` copies `src/x.swift:42`, `error:` copies `error`) unless the word is a URL with a port or an IPv6 address. The word highlights briefly and **Copied N characters** appears. That copy is yours: it goes on this device's clipboard and is not OSC 52, so it is allowed even when a remote clipboard write would be dropped.
- Touch and hold, then lift without moving, shows **Paste**. Text pastes as **Paste** on the bar does. An image (a screenshot, or a photo copied from Photos) is saved on the host like a chat-bar attachment, in the `oppi-ssh` folder under `$TMPDIR`, and its path is pasted, which Claude Code and pi read as the image. When the clipboard holds both text and an image, the text is pasted. **Paste** on the keyboard bar takes images the same way.
- Touch and hold, then drag, selects a range in a plain shell and copies it on release, with the same note. Selection never sends bytes to the host. In a mouse-reporting app the same gesture is a mouse drag (press, move, release) instead of a selection. A hold that has not moved yet sends nothing, so a mouse app gets no press or click from a hold that ends in **Paste**.
- Dragging a mouse-reporting app sends wheel steps. One wheel notch is three rows of finger travel, so Herdr (three lines per notch) tracks the finger. tmux (five lines per notch) runs a little ahead. The app moves whole lines, so a step goes out once the finger is halfway to the next one: the first notch comes a few points past a row and a half, and the text stays within about half a notch of the finger instead of trailing it. A small wobble back does not undo a step. A flick keeps going with the same native deceleration as local history; putting a finger down stops it and drops steps already queued. Wheel steps from one frame go in one SSH write, reported at the cell under the finger so a split-pane app (tmux, Herdr) scrolls the pane you flicked.
- On the alternate screen without mouse reporting (`less`, `man`, a git log pager, vim without mouse), a vertical drag sends ↑ and ↓, one per row of finger travel and timed the same way (the first a few points past half a row), with the same flick momentum and one write per frame. DEC 1007 (alternate scroll) is on by default, as in Ghostty. If the remote leaves that screen, or turns mouse reporting on or off, while a finger is still down or a flick is still coasting, that gesture is dropped: it does not type into the shell, does not send wheel steps, and does not jump local history. The next touch starts fresh.
- Otherwise, dragging reads local history. The text glides under the finger point for point, not a row at a time, and it starts moving with the finger's first few points of travel instead of after the system's drag threshold. A flick keeps native momentum and rubber-bands at the ends, and the scroll indicator is sized from the terminal's scrollbar. A scroll can stop partway through a row; the row below shows in the strip at the bottom, and a tap or selection there acts on that row. A drag released within half a row of the bottom is back at live. **Back to Live** returns to the bottom.
- The terminal has no navigation bar. **Back** (‹) is a small glass button at the top left. A second one at the top right holds the program-status symbol (while a program has reported), Herdr (when the host has it), and **…**. They float over the first rows and never change the terminal's size, so they never resize the remote shell. The … menu's header names the screen: the title the shell set, or the saved host. Swiping from the left edge goes back too, as does VoiceOver's two-finger scrub. Leaving the terminal does not resize the remote shell.
- While a docked keyboard is up (the chat bar or typing in the terminal), both fade out, and they come back when it goes down. Docked means on this display: iPhone, the Duo's inner screen, or iPad docked. A floating iPad keyboard leaves them, and so does a keyboard on the Duo's other display. A broken connection keeps them, so Back and Reconnect stay in reach. Swiping from the left edge goes back while they are faded. The remote shell resizes once per keyboard change.
- When Herdr or a blocked program wants you, an orange dot sits on Back. It goes away when the wait ends. VoiceOver reads **Attention pending** on Back.

A healthy connection shows no status banner. Connecting, disconnected, and network-changed copy, plus paste and input warnings, float over the terminal. They do not change its size or resize the remote shell. **Edit Host**, **Disconnect**, and **Reconnect** are in the … menu.

## Herdr

When `herdr` is on the host, the terminal checks Herdr's API (`herdr api snapshot`) every few seconds over the same SSH connection, in a separate command channel. A grid button appears beside **…** at the top right, orange while agents wait at an approval or question prompt. It opens a list of workspaces and agents. Each agent shows the same status symbol and label as the program-status glyph: Working (animated), Question, Done, or Idle. The focused workspace and agent are bold. Herdr decides the state from the agent's screen or its Herdr integration, and does not pass OSC 7501 through to this terminal. A Herdr version that lists a pane's OSC 7501 records in its API (`program_status`) is read the same way as records in a plain terminal: the records lead, a child's wait counts, and the blocked kind shows (Needs approval, Sign-in, Question). Without records, Herdr does not say which kind of wait it is, so a blocked agent reads as Question. Done means Herdr saw the agent go idle and nobody has looked yet, so a question Herdr does not recognize shows as Done. Oppi's `ask` extension tells Herdr's Pi integration when it waits, so a pi question reads as Question. An unrecognized Herdr state shows as Unknown. Tapping a row runs `herdr workspace focus` or `herdr agent focus` on the host. Hosts without `herdr` are checked once per connection and then left alone.

## Clipboard

When a program on the host copies text to the terminal's clipboard (OSC 52), the text goes on this device's clipboard and a short **Copied N characters** note appears over the terminal. Herdr forwards a pane's copy this way (copy-on-select, an agent's `/copy`), as does tmux with `set-clipboard on`. Only UTF-8 text of up to 1 MB, sent to the standard clipboard (`c`), is copied. Requests to clear the clipboard and writes to the X11 selection or primary buffer are ignored. Copying is write-only: the host can never read this device's clipboard, and clipboard queries get no reply. Oppi applies a remote copy only while that terminal's screen is showing and Oppi is in front; a terminal you left, or Oppi in the background, drops it. A double-tap or a long-press selection copy is your own action, not OSC 52, so it is allowed regardless of that gate. Paste is always your action, through **Paste** or ⌘V.

## Program status (OSC 7501)

The terminal answers the Program Status Protocol support query (`ESC ] 7501 ; ? ST`) with the revision 0.4 reply, which lists the states and kinds it accepts (`?:states=idle,working,done,blocked,error:kinds=permission,question,auth`), so programs that detect support first, such as Pi 1.1.0, start reporting. Reports (idle, working, done, blocked, error, with an optional app, title, and message) are kept per terminal following the [specification](https://www.superlogical.com/rex/docs/build/program-status): one record per id, a `clear` removes a record and its children, at most 256 records. `working` and `blocked` records are dropped when the shell shows its next prompt (OSC 133 A) or the shell or connection ends; `done` and `error` stay. Reset (RIS) clears everything. This reply is the only OSC reply the terminal sends; clipboard queries still get none.

While a program has reported, the top-right controls show a status symbol, not a word: a blue progress mark while working, an orange hand, question, or lock while blocked, and a grey dot at rest. Tap it for the list of programs, with this host named at the top. Done and Error show in green and red only until this terminal is on screen; looking at the terminal counts as seen, so a just-finished run holds its colour briefly and then settles to Idle. A record tree uses the same roll-up as a thread: a blocked record wins over a working root. Nothing shows until a program reports.

When any record is blocked, a card floats over the top of the terminal. It names the kind, the saved host, and the program's message. It does not change the terminal's size, and it is not a dialog: you answer in the terminal or the chat bar. If it covers the program's own prompt, tap it or swipe it up (VoiceOver: the Dismiss action); it folds into the status symbol, which stays orange and still lists the message. It stays away while the program repeats the same report, and comes back for a different kind of wait, the next time the program blocks, or a new message once the program's reports pause for a second (a message rewritten in a loop updates the card's text without bringing it back).

## Notifications and the bell

A program can notify the terminal with OSC 9 (`ESC ] 9 ; text ST`, iTerm2) or OSC 777 (`ESC ] 777 ; notify ; title ; body ST`, rxvt and Ghostty). The same card shows it, headed **Notification**, with the program's title and text on their own line, and leaves after six seconds or when you tap it. Notifications less than a second apart are one notification whose text updates, so a program printing them in a loop cannot hold the card up or bring it back. A blocked program comes first: while its card shows, a notification waits behind it, and folding one card away never brings back the other. A new card of either kind gives a warning haptic, at most once a second. OSC 9;4 progress reports are not notifications. A bell (BEL) gives a light haptic and no card, since shells ring it for ordinary things such as a failed completion; bells within one second count once.

The terminal hears these while its connection is open, including after you leave its screen ([Keeping a terminal open](#keeping-a-terminal-open)); it hears nothing once the connection has closed. Programs inside Herdr usually notify Herdr, not this terminal, and Herdr's own notifications use Kitty's OSC 99, which the terminal does not read yet.

## Credentials and host trust

- Profile metadata (host, port, username, sign-in choice, and Run on Connect) is stored in app preferences. Passwords are never stored there or logged. Each saved host has its own id. Changing that host’s hostname, port, username, or sign-in method cannot keep its password, and does not change another host’s password.
- An unsaved password is used for one connection attempt. Reconnect asks for it again.
- A saved password is in the app’s private Keychain, not the app group. It does not sync or migrate to another device. A device passcode is required to save it; reading it at connect requires Face ID, Touch ID, or device-passcode approval, which Oppi [reuses for 5 minutes](#approval-reuse). The saved secret is bound to that host’s id, so copying one host’s secret onto another host’s item does not sign in.
- On a physical device, the per-device P-256 SSH key is in the Secure Enclave. Signing requires user presence, reused for 5 minutes ([Approval reuse](#approval-reuse)). The simulator uses an explicitly labelled software key. Selecting password sign-in does not create a key.
- Trusted host keys are stored in the app-private, this-device-only Keychain, shared by SSH Terminal and Check a Machine. A changed host key blocks sign-in. **Forget Trusted Key** requires confirmation; independently verify why it changed before trusting its replacement.
- **Delete Host**, including swipe delete on the list, deletes that saved host and its saved password. It does not remove the per-device key or trusted host keys. Trusted host keys stay keyed by host and port. The device key stays one per device. If the host list cannot be read, saving is blocked until **Reset Host List** removes the unreadable list; add the hosts again after that. Reset does not search the Keychain.

## Keeping a terminal open

While Oppi is in the foreground, a connected terminal stays connected when you leave its screen: Back, another tab, another session. Tap that host in the list again (it reads **Connected**) and you get the same live channel and grid, with no reconnect and no sign-in. Oppi keeps one terminal per saved host, so at most as many as you have saved hosts. Connecting a host that already has one shows that terminal; **Reconnect** and a connect after the shell ended open a new one.

A terminal ends when you tap **Disconnect**, when the remote shell or command exits or the connection drops, when you save changes to the host or delete it, when you turn SSH Terminal off (from Settings → Experiments; no SSH screen has to be open), or when the [background grace](#network-and-reconnect) ends. Saving the host without changing anything keeps it.

While a terminal is off screen Oppi still reads its output and answers its terminal queries, and checks the connection after a network change. The Herdr list and program shortcuts load again when you return.

## Approval reuse

Face ID, Touch ID, or the passcode is asked when a sign-in needs your device key or a saved password. Oppi remembers that approval for 5 minutes, separately for the device key and for each host's saved password, so a reconnect in that window (**Reconnect**, or the automatic one on return) does not ask again. Oppi keeps its own approval for this; it does not widen the system's biometric reuse. The approval ends early when the 5 minutes pass, when App Lock locks or covers Oppi, and on any sign-in or approval failure; the next sign-in asks again. Approvals are never saved to disk, and a terminal that is already connected does not depend on them.

## Network and reconnect

When Oppi’s in-app Tailscale node is running, tailnet names (`*.ts.net` or `*.beta.tailscale.net`, with or without a trailing dot) use that node. Other hosts, and tailnet names while that node is stopped, use direct TCP through your current network, including a system Tailscale VPN if active.

Oppi checks SSH round-trip liveness every 60 seconds by opening and closing an empty session channel, with a 15-second reply timeout. It requests no shell, command, or PTY on that probe. Direct TCP also uses kernel keepalive probes. Failure closes the connection and shows **Disconnected** with **Reconnect**.

Entering the background keeps the shell running for about 25 seconds, still reading its output, under an iOS background task. Return within that time and nothing reconnects. A connect or reconnect still signing in or dialing when Oppi goes to the background is cancelled, and one that finishes there is closed again, so no session is left for iOS to suspend; a terminal screen you were on reconnects when you return. Otherwise Oppi closes the connection before iOS can suspend it (also if iOS ends the background task earlier), with the reason **Oppi went to the background.** Closing is deliberate: a suspended app would silently lose the bytes the host sends. When you return, a terminal that was on screen reconnects on its own, signing in like **Reconnect** (see [Approval reuse](#approval-reuse)); with App Lock on, after you unlock. A terminal you had already left is not reconnected. If that sign-in is cancelled or fails, the terminal shows **Disconnected** with **Reconnect**. After a Wi-Fi or cellular path change, Oppi checks the connection with one SSH round trip: a live shell carries on, and a dead one shows **Disconnected** with **Reconnect**. Those notices float over the grid and do not resize it. Reconnect always opens a fresh shell; it does not replay input. Use `tmux` on the host if work must survive a disconnect.

## Limits

- Hosts are saved on this device only. No private-key import, keyboard-interactive, or forwarding.
- The SSH library supports Ed25519/ECDSA host and user keys, Curve25519/ECDH key exchange, and AES-GCM encryption. RSA-only and legacy-only servers fail with an unsupported-algorithm error. A server that offers only keyboard-interactive cannot accept password sign-in here.
- Connection, authentication, and terminal-opening waits are bounded. A rejected credential, changed host key, unreachable host, or unsupported algorithm produces a visible error.
- Secure Enclave and biometric approval need physical-device testing. A simulator software key is not evidence of hardware protection.
